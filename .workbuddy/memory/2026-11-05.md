### 技术结论（会反复用到）
1. **`check-deps.ps1` 必须用路径解析而非行正则**：`crate::x` 行正则会漏掉 `rustfmt` 折行 use 树、`super::tools::`、字符串内 `//`/`/*`、`#[cfg(test)]` 中部插入。正解 = 注释/字符串状态机 + use 逻辑行拼接 + use 树展开 + `crate/super/self` 归一到绝对模块路径。
2. **PowerShell 语法错误返回退出码 1，`try/catch` 在解析阶段不执行** → 必须靠 CI 侧"结束标记"包装区分「脚本坏了(3)」与「代码违规(1)」。脚本用 UTF-8 **BOM** + `#Requires -Version 5.1` 才能在 5.1 下解析中文注释；`GetRelativePath`、`Join-Path` 三参形式是 PS6+ API，必须避开。
3. **`call_id` 由模型提供方给出，不保证跨轮唯一**（DeepSeek 系 `call_0`/`call_1` 每轮从 0 重来）。前端幂等判据只能收紧为"同名且仍 running"，M3 正确去重键是 rollout 的 `event_id`。
4. **取消态不能靠 `error` 文案匹配**（后端三处都在发"已取消"/"用户拒绝"）。当前用 `exit_code == null` + 轮次原因反推，已知不精确，根治需 `ToolCallEnd` 加 additive `result` 字段（SH-074）。
5. 前端测试断言要按 callId 作用域化 testid，否则一轮多工具调用时 `getByTestId` 直接抛多匹配。

- 收尾检查按 `git status` 新增文件清单比，**不要按命名前缀比**（`__*` 查完漏了 `zz_*` 的教训）。

### SH-074 协议字段（`ToolCallEnd.result`）
- 新增 `ToolCallResult { ok, error, cancelled, denied }`，`#[serde(default, skip_serializing_if = "Option::is_none")]`（`None` 不产生键）。
- **`result` 存在时是唯一状态判据**，`exit_code`/`error` 降级为证据字段仍保留可查。`result=ok` + `error` 非空 → 状态仍 `ok`，但文案必须渲染（中性色）。
- **节点级判据隔离**：`ToolCallNode.result?`；`turn.ts` 收敛仅在 `node.result !== undefined && node.status !== 'running'` 时跳过（联合条件——只判 `result` 会让漏写 status 的节点永久转圈）。
- **回退路径（result 缺失）不产出 `denied`**：旧事件显示「失败 + 用户拒绝」，与既有行为一致；任何情况下都不做 `error` 文案匹配。
- tone 取值源 = `node.result ?? node.status`；仅 `=== 'error'` 用 danger，其余中性色。`denied` 视觉复用 `bg-line2 text-primary`，**不新增 warning 色**（归 SH-041 主题层）。
- 前端协议枚举**单源在 `src/transport/types.ts`**；`nodes/types.ts` 用 `import type` + `export type { RiskLevel }` 再导出（`ApprovalCard` 仍从 nodes 取，只删不转发会编译失败）。
- 运行时未知 `result` 值必须归 `error`：`STATUS_META[status]` 为 undefined 后读 `.dot` 会同步抛错，而 **ChatView 没有 error boundary** → 一张坏数据白屏整个会话。组件侧用 `known in STATUS_META ? known : 'error'`。
- FF-2 快照已升级为**枚举变体穷举**（读 TS 源文件比对 `RiskLevel`/`ToolCallResult` 等），不再是"事件标签集合"。
