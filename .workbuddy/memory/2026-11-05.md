### 技术结论（会反复用到）
1. **`check-deps.ps1` 必须用路径解析而非行正则**：`crate::x` 行正则会漏掉 `rustfmt` 折行 use 树、`super::tools::`、字符串内 `//`/`/*`、`#[cfg(test)]` 中部插入。正解 = 注释/字符串状态机 + use 逻辑行拼接 + use 树展开 + `crate/super/self` 归一到绝对模块路径。
2. **PowerShell 语法错误返回退出码 1，`try/catch` 在解析阶段不执行** → 必须靠 CI 侧"结束标记"包装区分「脚本坏了(3)」与「代码违规(1)」。脚本用 UTF-8 **BOM** + `#Requires -Version 5.1` 才能在 5.1 下解析中文注释；`GetRelativePath`、`Join-Path` 三参形式是 PS6+ API，必须避开。
3. **`call_id` 由模型提供方给出，不保证跨轮唯一**（DeepSeek 系 `call_0`/`call_1` 每轮从 0 重来）。前端幂等判据只能收紧为"同名且仍 running"，M3 正确去重键是 rollout 的 `event_id`。
4. **取消态不能靠 `error` 文案匹配**（后端三处都在发"已取消"/"用户拒绝"）。当前用 `exit_code == null` + 轮次原因反推，已知不精确，根治需 `ToolCallEnd` 加 additive `result` 字段（SH-074）。
5. 前端测试断言要按 callId 作用域化 testid，否则一轮多工具调用时 `getByTestId` 直接抛多匹配。
