## 零、结论一页

| 问题 | 结论 |
| --- | --- |
| 要写哪几级 | 工作区根的**每一级祖先**（不含盘根），只补 `(RA,S)` |
| 授权掩码 | `FILE_READ_ATTRIBUTES \| SYNCHRONIZE` = `0x100080`，**非继承** |
| 谁拥有这些层级 | 盘根：TrustedInstaller/SYSTEM（不写）；`C:\Users`：SYSTEM（写不进）；`C:\Users\<user>` 以下：用户自己 |
| 要不要管理员 | 只在「工作区位于 `C:\Users\` 下」时需要一次管理员（为了 `C:\Users` 那一级）；`D:\` 等工作区不需要 |
| 代价 | 单级 DACL 写入 24–26s（整棵子树继承重算的固定成本，非 I/O） |
| 什么时候写 | **后台线程**，启动后异步；exec 永不等待 |
| 会不会还原 | **不还原**。持久化就是方案本身；账本只记「我们加过哪几级、加之前有没有」 |
| 四处写权限 | 工作区根 / `%TEMP%` / `~/.cargo` / `~/.rustup` **也持久化**（2026-11-12）：首次约 40s，之后每次启动探测命中、零写入 |
| 判定缺不缺 | 按真实 DACL 探测（命中 0.3–2ms/级），**不信**状态位、**不信**账本 |

> 旧版方案作废的理由：它要在安装期（或首次运行）预置盘根。2026-11-12 的零写入对照（A/B 两组）
> 证明**盘根不需要 ACE**——`C:\`、`D:\` 一次都不写，只要用户自有层级补齐，冷构建 exit 0（1m08s）。

## 一、判定口径（写反过一次，别再踩）

容器对某个对象做 `metadata` / `read_dir`，需要**该对象自身**有一条命名容器 SID 的 ACE；
**穿过祖先不需要 ACE**（`SeChangeNotifyPrivilege` 由对象管理器实现，整条路径的
`FILE_TRAVERSE` 被绕过）。所以：

- 「盘根没有 ACE」≠「路径在盘根就断了」。断点永远是被访问的那个对象。
- 「能 `cd` 进去」不能证明「能读属性」，反之亦然。这两件事的判据不同，别混。

为什么非得补：容器里的构建工具用 `glob` 逐段 `fs::metadata` 探测路径，而
`glob-0.3.4` 在 `fill_todo` 的 if 守卫里对失败的字面层级**静默跳过、不报错**
（`glob-0.3.4/src/lib.rs:933-939`；该 crate 内没有 `flatten`），随后 `tauri-utils`
再用 `.flatten()` 吞掉 `GlobError`（`tauri-utils-2.10.2/src/acl/build.rs:76-78`）。
> **归因已更正（2026-11-12）**：原文写作「`glob-0.3.4::fill_todo` 对任何一级失败都 `.flatten()`
> 静默丢弃」，归因错位——`.flatten()` 在 `tauri-utils`，不在 `glob`。**结论不变**：权限清单会静默为空。
> 证据摘录见 `docs/evidence/2026-11-12/code-refs-2026-11-12.md`。

实测后果是 `tauri-build` 收集不到 `core:*` 权限，冷构建报
`Permission core:window:allow-minimize not found`，全程没有一句「拒绝访问」——这也是最初
把根因误判成「遍历权」的原因。（该冷构建日志**未入库**，本审计判「无法核实」；
复现方式见 `docs/evidence/2026-11-12/README.md` 的待测表。）

掩码逐档实测（容器内 `fs::metadata`）：

| 掩码 | `metadata` | `read_dir` | 结论 |
| --- | --- | --- | --- |
| `FILE_READ_ATTRIBUTES`(0x80) 单独 | 拒绝 | 拒绝 | 不够 |
| `READ_CONTROL` 单独 | 拒绝 | 拒绝 | 不够 |
| **`(RA,S)` = 0x100080** | **通过** | **拒绝** | **采用** |
| `(R)` / `(RX)` | 通过 | 通过 | 越界（含 `FILE_LIST_DIRECTORY`，暴露条目名） |

因此 `Access::Ancestor` **禁止**用 `Access::Traverse` / `FILE_GENERIC_EXECUTE` 表达。

> **本条为「待测」**（2026-11-12 审计）：掩码最小集需要给祖先目录写四种 ACE 才能实测对照，
> 本次只读审计禁止 DACL 写入，故不升级为「有证据」。测法与前置条件见
> `docs/evidence/2026-11-12/README.md`；当前令牌的只读观测（`AccessCheck` 本机不可用、
> 退化用 `CreateFile`）在 `docs/evidence/2026-11-12/token-access-probe-*.jsonl`。

## 二、为什么必须后台，且绝不在第一次 exec 里补

`SetNamedSecurityInfoW` 对未保护 DACL 会触发整棵子树的继承重算，与 ACE 是否继承无关。
本机实测：

| 对象 | 写入耗时 |
| --- | --- |
| `D:\MyWorkspace` | 25 570 ms |
| `D:\MyWorkspace\SHANIU` | 25 359 ms |
| 第二次探测（已存在） | 1–2 ms、零写入 |
| 回滚（还原） | 25 152 / 25 392 ms |

> **本节数字为「待测」**（2026-11-12 审计）：计时无落盘产物，且需要真实写盘才能复测；
> 测法（首次/二次各 3 次 + 保留账本与计时日志）见 `docs/evidence/2026-11-12/README.md`。

放 exec 路径上，用户第一条命令要卡半分钟以上。所以：

- **启动后异步补**（`sandbox::provision_ancestors_in_background`），入队即返回
  （实测 **281–292µs**），执行体在独立线程 `shaniu-ancestor-ace` 上跑；
- **exec 路径上的四处写权限也在同一线程里先做**（工作区根 / `%TEMP%` /
  `~/.cargo` / `~/.rustup`），且**同样是持久的**（2026-11-12 改，见 §3.3）：
  首次写一次（本机约 40s，工作区根 24s 占大头），此后每次启动只探测、零写入。
  实测首条命令的准备开销从 **5 868 ms 降到 35 ms**（复跑 2.6 ms）；
- 预置未完成时 exec **照常执行**，不自旋、不等待。自报里带
  `ancestors=preparing`，失败提示为「沙箱正在准备文件权限，稍等重试就好」；
- 有新工作区根第一次被解析时（`app_container_scope`）再入队一次，同一根只排一次。

## 三、实现结构

| 位置 | 职责 |
| --- | --- |
| `acl::ensure_ancestor_grant(dir, sid)` | 单级：先按真实 DACL 判有无覆盖 `(RA,S)` 的**显式** ACE → 有则 `AlreadyPresent`（零写入）；无则写一条**非继承** ACE |
| `acl::has_any_explicit_grant` | 写之前问「这个 SID 在这级上有没有任何显式 ACE」（掩码不覆盖也算），供账本 `existed_before` |
| `acl::ancestor_chain(dir)` | 盘根以下 → 父目录的祖先链，**不含自己、不含盘根** |
| `acl::grant_scope_persistent(dir, sid, guarded, ledger)` | 工作区根 / temp / 工具链的**持久**写权限入口：同一套「按真实 DACL 探测 → 幂等跳过 → 过宽根拦截」，但**不写备份**；写成功才按 `kind=scope` 记账（掩码 + 可继承） |
| `mod::provision_ancestors_in_background(roots)` | 入队 + 起线程；**先**做 exec 路径上的四处写权限（工作区根 / temp / 工具链），**再**补祖先 `(RA,S)`；`ANCESTOR_CLAIMED` 去重、`ANCESTOR_CANCEL` 逐级可取消、失败只记 warn |
| `mod::ancestor_state()` | `Idle / Preparing / Ready / NeedsAdmin`，**仅用于自报**，不参与「缺不缺」判断 |
| `mod::execution_note` | 执行类工具结果末尾追加 `ancestors=preparing\|needs_admin` |
| `mod::shutdown` | 先置取消再走原有还原/删 profile；**不等**后台线程（DACL 写入不可中断） |
| `appcontainer::derived_sid` | 只派生 SID、**不创建 profile**：后台若走 `ensure()`，会在 `build_runtime` 之前建好 profile，让 `owns_profile` 判成 false、退出时漏删 |
| `acl::persistent_ledger_path` / `append_persistent_ledger` | 账本 `sandbox/ancestor-ace.jsonl`（故意不放 `acl/`，那层是**会还原的**备份台账） |

### 3.1 账本格式

每级一行 JSON：

```json
{"kind":"ancestor","path":"D:\\MyWorkspace","sid":"S-1-15-2-1983...","mask":1048704,
 "inherit":false,"existed_before":false,"added_at_ms":1762930000000}
{"kind":"scope","path":"D:\\MyWorkspace\\SHANIU","sid":"S-1-15-2-1983...","mask":1245695,
 "inherit":true,"existed_before":false,"added_at_ms":1762930000000}
```

- `kind`：`ancestor`（`(RA,S)`、非继承）/ `scope`（写权限、`(OI)(CI)` 继承）。
  **老版本写的行没有这个字段，一律按 `ancestor` 处理**；
- `existed_before:false` → 这条 ACE 是我们独创的，卸载/回滚时才允许删；
- `existed_before:true` → 之前已有该 SID 的显式 ACE（哪怕掩码不够），**不许**把别人的记成我们的；
- 只在**真的写入成功**后追加；写入成功但账本记失败时打 warn（ACE 已生效，只是回滚精度下降）。

### 3.2 盘根不写（一个必须记下的 bug）

`ancestor_chain` 的第一版把盘根也算成一级（`D:\MyWorkspace` 的链里有 `D:\`），与它自己
注释里写的「不含盘根」相反。后果：本机首跑把状态永久钉在 `needs_admin`——`D:\` 的 owner 是
TrustedInstaller/SYSTEM、普通用户没有 `WRITE_DAC`，永远写不进。
已改为 `parent().parent().is_none()` 即断，单测断言同步改掉（原先那条断言 `C:\` 在链上）。

### 3.3 四处写权限也持久化（2026-11-12 再改）

工作区根 / `%TEMP%` / `~/.cargo` / `~/.rustup` 原来「备份 + 退出还原」，于是**每次启动**
都要整树重写一遍（本机约 40s，工作区根 24s 占大头）。用户不接受这条尾巴，对齐 dsh
（README:130「写一次常驻复用」）改为持久化：

- 走 `AclManager::grant_scope_persistent`：探测 → 命中即跳过 → 否则写一条 `(OI)(CI)` Write，
  **不写备份**（`sandbox/acl/` 下不会出现这四处的 `.dacl`），写成功按 `kind=scope` 记账；
- exec 路径与后台预置**共用同一个入口**。这一点是必须的：如果 exec 还走旧的有备份入口，
  它一旦补写就会在退出时被还原，把持久 ACE 抹掉；
- 备份语义只留给**会随会话消失**的授权（MCP 每 server 一个容器 SID，release 时精确撤销）；
- 为什么可以不要还原：见 §四 第 4 条（只读档的强制点在策略层，不在 DACL）。

### 3.4 默认关的开关

`ANCESTOR_ENABLED` 默认 `false`，只有 `lib.rs::run` 在
「`mode == workspace_write` 且 `os == appcontainer`」时打开。原因不是洁癖：
`write_scope` 含 `%TEMP%`，单测/集成测试的临时工作区一旦触发后台预置，就会顺着
`%TEMP%` 的链一路写到 `C:\Users\jun`（25s×N，且永久改动用户目录）。默认关保证
「测试不写真实盘」，探针要测就显式打开。

## 四、已知边界

1. **`C:\Users` 写不进**（owner=SYSTEM，普通用户无 `WRITE_DAC`）。因此工作区落在
   `C:\Users\<user>\...` 下时，该级永远是 `needs_admin`；`glob` 式的逐段探测会断在
   这一级，需要用户以管理员运行一次 SHANIU 才能补齐。状态条与工具自报都会带
   `ancestors=needs_admin`，不静默。
2. **cmd 内建命令不能用来验 `metadata`**：实测同一条 `(RA,S)` 下
   `[IO.File]::GetAttributes` 成功，而 `if exist` / `attrib` 报拒绝或「找不到路径」——
   cmd 内建是按**父目录** `FindFirstFile` 解析的，要的是父目录的 `FILE_LIST_DIRECTORY`。
   探针因此只用 PowerShell 的 `GetAttributes` 作 metadata 载体。
3. **`%TEMP%` 的残留**：旧版本在 `%TEMP%` 上留过可继承容器 ACE `(OI)(CI)(M,DC)`
   （本机已清除）。它属于「残留导致假绿」的典型：在其下新建的探针目录会**继承**它，
   于是「容器能写工作区」可能只是残留的功劳。探针工作区已迁到
   `%USERPROFILE%\.shaniu-probe`（父链无我们的 ACE），绿只可能来自当场显式授权。
4. **切到只读档后，残留的写权限 ACE 还在盘上，但没人能用它**（2026-11-12 评估）：
   - 只读档的强制点在**策略层**：`prepare_spawn_with` 对 `SandboxMode::ReadOnly` 直接
     `PolicyDenied`（不经子进程），`prepare_stdio`（MCP）同样先按档位拒；也就是说
     **只读会话里根本不会创建容器、不会有容器进程**，那条 ACE 没有主体可承载；
   - 应用正常退出会删掉自建的 AppContainer profile，SID 在盘上变成「未知账户」，
     下次启动按 profile 名派生回同一个 SID（`derived_sid` 是名字哈希，不是随机），
     持久 ACE 才能跨重启复用——这也意味着**没有容器就没有可用主体**；
   - 同机另一个实例若正跑在工作区可写档，它本来就能写（与是否持久化无关）；
   - 结论：`needs_admin` 与只读档都不依赖「退出还原」来实现强制。**唯一真实代价**是
     卸载后盘上会留下指向已不存在 SID 的 ACE，这由账本 + 卸载步骤解决（§六）。
5. **`write_scope` 含 `%TEMP%`**（用户 2026-11-08 决定：工作区根 / temp / 工具链）。
   现在这条授权是**持久**的，所以测试进程跑一次就会留下它（不再靠 `shutdown()` 还原）。
   手工清：
   `icacls "$env:TEMP" /remove:g "*S-1-15-2-1983691489-…"`（`.cargo` / `.rustup` 同理）。
   **这不影响探针可信度**：探针工作区不在 `%TEMP%` 下（见第 3 条）。
6. **备份还原可能抹掉持久 ACE（罕见，自愈）**：MCP 授权会为同一路径拍一份快照；若快照早于
   exec 的持久写（例如启动 24s 内就先起了 MCP），退出时 `restore_all` 会把快照写回，
   连带抹掉持久 ACE。`restore_all` 现在会在还原后复查并打 warn
   （「持久写权限被本次备份还原抹掉（下一次启动会重新补齐）」）——**不在退出路径重写 DACL**，
   下一次启动探测到缺失会补一次。正常顺序（先启动预置、后起 MCP）不会触发。
7. **账本不跨实例加锁**：多实例同时预置同一级只会重复一次探测，写 DACL 是幂等的。

### 5.1 「读隔离」断言现在到底证明什么

`sandbox_probe` 不再声称「整个文件系统都读不到」。它现在证明的是：

- **按对象**：容器能读的只有被显式授予 ACE 的对象（工作区根、`%TEMP%`、工具链目录）；
- **路径上路过不算**：祖先只给 `(RA,S)` 时，容器能 `stat` 它、但列不出条目、也读不到它下面
  未授权的文件（用例 ③）；
- **正向对照必须成立**：如果连工作区都列不出来，前三条一律不算数（用例 ④）。

旧版这两条对照都有假绿风险，已修：`for %f in (<path>/*)` 里的 `/` 被 cmd 当成选项分隔符，
把最后一级目录吃掉，`%f` 展开成上一层的同名文件——于是 `contains("LISTWS:inside.txt")` 会
「碰巧」满足。现已改用 `\*` 并逐行校验路径结尾。

## 六、卸载 / 回滚（按账本精确删除）

持久化之后，盘上会留下两类 ACE：祖先 `(RA,S)`（`kind=ancestor`）与四处写权限
（`kind=scope`）。两者都在 `sandbox/ancestor-ace.jsonl` 里，卸载器按下面顺序处理：

1. 读账本；**缺 `kind` 的老行按 `ancestor` 处理**；
2. **只处理 `existed_before:false` 的行**——`true` 说明写之前该 SID 已有别人的显式 ACE
   （`SetEntriesInAclW` 会把掩码合并进那一条），删了就是删别人的授权；
3. 按 `(path, sid)` **去重**后逐条调用 `acl::revoke_ace(path, sid)`（只删该 SID 的显式 ACE，
   不动继承 ACE、不动其他主体）；
4. 同一个 `path` 若既有 `scope` 又有 `ancestor` 行（工作区根恰好是另一个根的祖先时才可能），
   一次 `revoke_ace` 就把该 SID 的 ACE 全删了，**不要重复调用**；
5. 撤销同样会触发整树继承重算，按 25s/级预算，且应在卸载器里**异步**做，不要卡住卸载界面；
6. 跑完后可选复核：`has_explicit_grant(path, sid, mask)` 应为 false；应用仍在使用时不要跑。

运行期的 `acl/` 备份台账**只剩 MCP 每 server 的授权**（会随 `shutdown()` /
`recover_pending()` 还原），与本文件的持久化账本**互不相干**，不要合并。
`kind=scope` 的行不该出现在 `acl/*.dacl` 里——出现了说明这条走错了入口（§3.3 第一条）。
