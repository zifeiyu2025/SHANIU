## 1. 定位

| 面 | 定位 | 边界判据（满足即属本层） |
| --- | --- | --- |
| 前端 / UI | **全量跟随 DSH** | 界面形态、组件结构、交互序列、文案键、设计令牌都以上游 `packages/client/**` 为准；上游没有的 UI 必须先在提交说明与 `docs/05` 写明「为什么必须自造」 |
| 后端 / 宿主 | **自研，不追 DSH 架构** | 允许与上游后端在模块划分、进程模型、存储布局上完全不同；只对"前端能观察到的东西"负责（见 §2） |

**推论（可直接执行）**：

1. 后端不得为了实现方便去改 vendored 前端；要改前端必须先回答"上游是不是这样"。
2. 后端可以整体替换实现（例如事件改走 loopback WS、存储改侧车文件），只要 §2 的五类可观察面不变。
3. 判断某个改动属于哪一层：**它会改变用户看到/听到/点到的任何东西吗？** 会 → 前端对齐问题；不会 → 后端自由区。

## 2. 对齐判据

**判据只有一条：用户可观察行为一致。代码相同不算数。**

| 可观察面 | 判定标准 | 现有守护手段 |
| --- | --- | --- |
| 事件类型与字段 | 同一操作产生的 `EventMsg` 类型名、字段名、字段语义与上游一致；新增字段必须 optional | 事件 schema 快照测试（`src-tauri` cargo test） |
| 文案 | 同一状态下用户读到的文字与上游对应文案一致（含空态、错误态、确认框按钮） | vitest 渲染断言 + 文案键对照 |
| 界面形态 | 同一状态下组件结构、层级、可见元素集合一致（不要求像素级） | 受影响组件渲染验证（`AGENTS.md` §4） |
| 交互序列 | 完成同一目标所需的点击/输入步骤数一致，不额外插入自有弹窗或二次确认 | 真机走查 + 录制回放规格（`scratch/spec-replay/spec.md`） |
| 错误呈现 | 同类失败在同样的位置以同样的形态出现（toast / 行内 / 面板），可恢复动作一致 | 契约测试的错误路径用例 |

**反例（明确不算对齐）**：

- 文件哈希 `same` 但用户看到的行为不同 → 不合格，按缺陷处理。
- 后端接口"语义等价"但前端要改一行才能接上 → 不合格，属于 §3 的偏离，必须登记。
- 界面"看起来差不多"但步骤多一步/少一步 → 不合格。

## 3. 偏离规则

**定义**：任何会影响前端表现的后端偏离，都是一个"需登记偏离"。

| 步骤 | 动作 | 产物 |
| --- | --- | --- |
| 1 | 判定是否影响前端表现（§2 五类可观察面任一） | 影响 → 继续；不影响 → 无需登记 |
| 2 | 在 `align/overrides.json` 对应路径/目录前缀写 `reason` 与 `guard` | 一条 JSON 记录 |
| 3 | 在 `docs/07-vendor本地改动清单.md` 记录改动点（若动的是 vendored 文件）或偏差说明（若动的是行为） | 清单条目 |
| 4 | 补一条守护用例，证明"偏离后的行为"与"改回对齐会红" | 测试用例路径写进 `guard` |

**必填字段**：

| 字段 | 要求 | 不合格示例 |
| --- | --- | --- |
| `reason` | 写清"为什么必须偏"，并指向 `docs/05` 卡号或 ADR | "兼容性调整" |
| `guard` | 一个可执行的测试文件::用例名，或明确写"无自动化守护 + 真机步骤" | 留空 |
| 影响面 | 在 `docs/07` 或 `docs/05` 写明用户会观察到什么不同 | 只写"内部实现不同" |

**红线**：

- **未登记的偏离视为缺陷**，优先级等同功能 bug。处理方式二选一：补登记，或改回对齐。
- 禁止用"体验更好"作为登记理由绕过对齐；确属体验改进的，先按 §11.3 说明再动手（`AGENTS.md`）。
- 偏离登记不是许可证：登记过的偏离仍然要过 §2 的守护用例，否则登记本身失效。
- `align/ledger.md` 里 `review: needs-review` 的条目 = 未登记偏离的机械证据，必须清零后才能算一次对齐收口。

### 4.2 跨平台分支只读清点（2026-11-11）

**口径**：只统计 `src-tauri/src` 与 `src-tauri/tests`；`src/dsh/**` 是 vendored 上游，其 `process.platform` 分支属对齐账本管辖，**不在可删范围**（删了即 drift）。

| 形态 | 处数 | 文件数 | 说明 |
| --- | --- | --- | --- |
| `#[cfg(windows)]` | 40 | 9 | 属性行；删除后函数/块变为无条件编译 |
| `#[cfg(not(windows))]` | 16 | 8 | 非 Windows 桩块，是真正"可删"的部分 |

### 4.3 已定案：保留分支 + 编译期守卫

**决定（2026-11-11，用户拍板）：不删跨平台分支，改为在 `lib.rs` 顶部加一行编译期守卫。**

```rust
#[cfg(not(windows))]
compile_error!("SHANIU 仅支持 Windows（见 docs/10 §4）");
```

**理由**：

1. **收益不成比例**：删分支合计约 119 行（13 个文件），约占 `src-tauri/src` 总量 1% 以下；不产生任何用户可观察变化。
2. **成本落在受保护路径**：16 个 `#[cfg(not(windows))]` 桩块中有 2 处在 `sandbox/mod.rs`（fail-closed 桩，返回 `CreateFailed`）。按 `AGENTS.md` §2 需逐 diff 确认 + 探针全绿，一次机械清理换来的是安全边界的高成本复核。
3. **语义更强**：`compile_error!` 让非 Windows 构建直接失败，比"删掉分支后靠缺失符号间接失败"更早、更明确。
4. **可逆**：一行改动，回滚即恢复原状；删 119 行后若要恢复只能翻历史。
5. **不碰沙箱**：守卫只存在于 `lib.rs`，`sandbox/` 零改动。

**执行归属**：代码改动**不在本文档批次**，由写 `src-tauri/` 的线执行；本文只落定结论。

**验收**：`cargo build` 在 Windows 上通过；在非 Windows 目标上（`cargo check --target x86_64-unknown-linux-gnu`，若工具链可用）构建失败且错误信息含 `SHANIU 仅支持 Windows`。

## 5. 不做云

| 排除项 | 判据（命中即不做） |
| --- | --- |
| 云同步（配置 / 会话 / 工作区） | 需要服务端存储或账号 |
| 分享（会话链接、快照分享） | 需要服务端托管内容 |
| 点赞 / 收藏 / 排行榜 / 社区 | 需要服务端聚合他人数据 |
| 任何"登录才能用"的主流程 | 本地无账号不可用 |

**保留**：本地自用能力（本地存储、本地搜索、本地导出）不受此限；用户自带 API Key 直连模型端点是"本地配置"，不算云能力。

**判据落地**：新增功能评审时先问三句——① 没有网络还能不能用？② 要不要注册账号？③ 数据是否必须离开本机？任一为"是/要/必须"即触发本节，默认不做，除非用户单独批准。

## 6. 搜索

| 项 | 规定 |
| --- | --- |
| 保留范围 | 基础网页搜索能力保留（`src-tauri/src/tools/web/`） |
| 默认通道 | **免 key 的抓取兜底**（`bing-scrape`），开箱可用，不需要用户配任何凭据 |
| 可插拔 | 预留 key-based provider 接口；**用 key 的 provider 以后按插件引入**，本期不内置任何需要 key 的搜索源 |
| UI | 不新增搜索专用 UI |
| CSP | 不新增 CSP 指令（抓取在宿主侧完成，前端不直连第三方域） |

### 6.1 硬要求：失败必须可区分

**搜索失败必须显式报错，不允许返回空结果。** 空结果只能表示"真的没有结果"。

| 失败原因 | 必须产出 | 禁止行为 |
| --- | --- | --- |
| 超时 | 显式错误：`搜索超时（{ms}ms）` + 可重试提示 | 返回 `results: []` |
| 非 200 | 显式错误：含状态码与目标 host | 当作"无结果" |
| 解析失败 / 选择器空 | 显式错误：`无法解析搜索结果页`（区分于"解析成功但 0 条"） | 静默吞掉 |
| 网络不可达 / DNS 失败 | 显式错误：含原因 | 返回空 |
| **真的 0 条** | 正常返回 `results: []` + 一个明确的"未命中"标记 | 抛错 |

**为什么**：返回空结果会让模型误判"这个话题没有资料"，进而编造或放弃；这是错误信息污染上下文，比报错更贵。

**验收方式**：对四种失败各一条单测（桩服务/本地断言），断言错误类型与文案；再加一条"真 0 条"用例，断言不抛错且 `results` 为空。规格见 `scratch/spec-search/spec.md`。

**当前状态（2026-11-11 只读核对）**：机制**已有**——`src-tauri/src/tools/web/search.rs` 定义 `SearchFailure{Parse, Blocked, Network}`，`SearchError::guidance()` 给三种失败不同的下一步建议，`finish()` 明确区分"确实没有结果"与"结构变了"；`FallbackProvider` 已存在（key provider 的接缝就在此）。**未核**：每种失败各一条守护用例是否齐备、超时与非 200 是否在文案上可分辨。在 `scratch/spec-search/spec.md` 的 §5 矩阵逐行验收前，不得对外宣称"搜索失败语义已验证"。
