## 一、要解决的问题（一句话）

workspace-write 容器要在**盘根以下、工作区根及以上**的每一级祖先对象上有一条命名容器 SID 的 ACE（实测最小掩码 `FILE_READ_ATTRIBUTES|SYNCHRONIZE` = `icacls` 的 `(RA,S)`：够 `fs::metadata`，不含 `FILE_LIST_DIRECTORY`，不给列举；`FILE_READ_ATTRIBUTES` 单独**不够**，`FILE_GENERIC_EXECUTE` 够但不是最小）。**盘根不在链上**：`C:\`、`D:\` 一处不写也能跑通（`glob` 从不 stat 盘根）。`C:\Users` 这种层级只有 SYSTEM/Administrators 能改 DACL（本机实测当前用户 `WRITE_DAC` 不可得），非提权用户运行时补不上。exec 路径同步补写实测 86s/次（计时无落盘产物，属待测），已从 exec 路径撤回；启动后的后台线程仍会补（持久 ACE，见 `docs/14`）。

> 归因更正（2026-11-12 实测）：此前写的「祖先缺 TRAVERSE」「路径在盘根就断了」是**推断，不是证据**。实测表明途中各级遍历不受影响，断点是目标对象自身的 `READ_ATTRIBUTES`。详见 §二「关键证据」。

## 二、现状边界（实测，不美化）

| 事实 | 数据 |
| --- | --- |
| 非提权能改的祖先 | `%USERPROFILE%`、`AppData`、`AppData\Local`、`%TEMP%`、工作区自身 |
| 非提权改不了的祖先 | `C:\`（owner=TrustedInstaller）、`C:\Users`（owner=SYSTEM，当前用户 `WRITE_DAC` 不可得）、`D:\`（owner=SYSTEM）。**其中 `C:\`、`D:\` 不在需要写的链上**，真正卡住的只有 `C:\Users` 这一类中间层 |
| 写一条不继承 ACE 的代价 | 系统要重算整棵子树。逐级：`C:\Users\<user>` 62.4s、`AppData` 30.5s、`AppData\Local` 13.4s、`AppData\Local\Temp` 1.4s；快照 0–1ms、备份 0ms，时间全在 `SetNamedSecurityInfoW` |
| 端到端影响 | 单次 spawn（进程内首次 workspace-write）中位 **11.6s → 86.4s**，最差 163.6s；退出还原中位 86.0s（5 次实测） |
| 关键证据（2026-11-12，零 DACL 写入的一次性探针） | 容器令牌 `whoami /priv` 只有 `SeChangeNotifyPrivilege`（**已启用**），**没有** `SeBackupPrivilege`；令牌是 lowbox（`TokenIsAppContainer=1`，包 SID = 由 `Shaniu.Sandbox.v1` 派生的固定值）。对 `C:\`、`C:\Users`、`C:\Users\jun`、`AppData`、`D:\`、`D:\MyWorkspace`、`D:\MyWorkspace\SHANIU` 与其中深层文件：`AccessCheck`（先用本进程令牌自校验必须通过，证明管线正确）对 `FILE_TRAVERSE` / `FILE_READ_ATTRIBUTES` / `FILE_LIST_DIRECTORY` / `FILE_READ_DATA` **全部 DENIED**，模拟令牌下的 `GetFileAttributes`/`FindFirstFile`/`CreateFile` 与容器内 `cmd` 实测全部 err 5；`icacls` 证实这些对象上**没有任何命名容器 SID 的 ACE**（`C:\`、`C:\Users`、`C:\Users\jun` 上只有别的包的 `S-1-15-3-65536-*` 能力 SID，本令牌不持有）。（原始输出未入库，本审计判「无法核实」；可复跑脚本与待测清单见 `scratch/evidence-2026-11-12/README.md`，容器令牌需用 `-TokenPid` 指向活体进程。） |
| 关键证据：**遍历不是断点** | 同一令牌在容器内 `for %f in (<%TEMP%>\*)` 能正常列举——`%TEMP%` 有容器 SID 的 ACE，而途中 `C:\Users\jun\AppData`、`AppData\Local` 一条都没有。`sandbox_probe::sandbox_can_write_inside_workspace` 同样在无祖先 ACE 的前提下通过。⇒ 途经各级的 `TRAVERSE` 由已启用的 `SeChangeNotifyPrivilege` 绕过，**「路径解析在盘根就断了」不成立**。 |
| 探针口径的坑 | 容器内 `cmd /C dir` 对**已授权**目录也报「拒绝访问」（`dir %TEMP%` rc=1，而同一目录 `for` 列举正常），不能拿来当证据；有效口径是 `for` / `FindFirstFile` 与 `AccessCheck`。 |
| 决定性实验（2026-11-12，A/B 两组，各跑一次真实 `cargo build` 冷目录） | **B 组（零 ACE）**：`cargo` 能起，但立刻 `error: could not find Cargo.toml`（exit 101）——连工作区自身都不可读。**A 组（只给用户自有层级）**：hello 级 1.18s 成功；本仓库冷 target 39.5s 编译完全部依赖后，卡在 `tauri-build` 的权限清单（`Permission core:window:allow-minimize not found`），全程无 err 5。定位（**归因已更正 2026-11-12**）：`glob-0.3.4` 对模式里每段**字面目录**调 `fs::metadata`，失败时在 `fill_todo` 的 if 守卫里**静默跳过、不报错**（`glob-0.3.4/src/lib.rs:933-939`，该 crate 内无 `flatten`）；随后 `tauri-utils` 再 `.flatten()` 吞掉 `GlobError`（`tauri-utils-2.10.2/src/acl/build.rs:76-78`）。原文写作「`.flatten()` 静默丢弃」属归因错位，**结论（权限清单静默为空）不变**。容器对 `D:\MyWorkspace`、`D:\MyWorkspace\SHANIU` 无 ACE → 权限清单收集为空。给这两级各补 `(RA,S)` 后**完整通过**：exit 0、1m08s、`Finished dev profile`，`C:\`/`C:\Users`/`D:\` 一处未写。 |
| 需要写的层级（按本机实测） | 盘根（`C:\`、`D:\`）**不写**；写「盘根以下 → 工作区根」的每一级。本机 `D:\MyWorkspace`、`D:\MyWorkspace\SHANIU`：owner=当前用户、`WRITE_DAC` 可得 → **免管理员**。若工作区在 `C:\Users\<user>\...` 下，`C:\Users`（owner=SYSTEM、`WRITE_DAC` 不可得）也在链上 → **需管理员**。 |
| 结论 | **exec 路径**不做祖先写入（已撤回）；但**应用启动后的后台线程会写**（`lib.rs:3119-3120` → `mod.rs:531/627`），写的是持久 ACE，见 `docs/14`。**盘根不需要写**，只需写「盘根以下～工作区根」每一级；这条链随工作区路径变化，安装期无法预先知道，因此安装期预置只覆盖固定位置（`C:\Users` 等），工作区相关的那几级只能运行期补（用户自有时免提权、代价是下面的重传播）。 |

固定 SID 的可行性：exec 容器名固定为 `Shaniu.Sandbox.v1`，AppContainer SID 由名字确定性派生，**所有机器一致**——安装期可以精确写出这一条 ACE。（MCP 容器 SID 由 server id 派生，安装期不知道，仍需运行期处理；其祖先通常落在用户可写层级，但同样会撞上 `C:\Users` 这类中间层。）（跨机一致性未测，属待测；测法见 `scratch/evidence-2026-11-12/README.md`。）

## 三、三条路子

| # | 方案 | 做法 | 工期 | 风险 |
| --- | --- | --- | --- | --- |
| A | **安装期预置（正解）** | MSI/安装器的提权自定义动作，给**盘根以下、且位置固定**的那几级（`C:\Users` 等）写一条**不继承**的 `FILE_READ_ATTRIBUTES\|SYNCHRONIZE` ACE（trustee = 固定容器 SID）；工作区相关的那几级随用户路径变化，只能运行期补（用户自有时免提权）；卸载时按同一 SID 精确删除 | **2–3 人日**（含安装/卸载/回滚/校验用例） | ① 工作区落在 `C:\Users\<user>` 之外的非用户自有层级时仍然坏；② 企业组策略/安全基线可能拒绝写这些 DACL（安装要可回滚）；③ 预置点必须可枚举，否则卸载残留 |
| B | **首次运行一次性提权** | 首次启动弹一次 UAC，跑内置 `sandbox-prep` 子命令做与 A 相同的写入；结果落标记文件 | **1–2 人日** | ① 用户拒绝 UAC = 仍然坏，必须明确提示；② 杀软/EDR 对「应用自提权改盘根 ACL」敏感，易被标记；③ 与 A 不冲突，可作 A 失败时的兜底 |
| C | **放弃 AppContainer 读隔离**（对齐 dsh 的 WRITE_RESTRICTED） | 只用受限令牌 + Job，不再需要祖先 traverse | **1–2 人日**（含探针/文档改写） | 产品边界倒退：读隔离（SH-021）与 loopback 隔离一起失效，沙箱只剩写约束。**不建议**，仅登记 |

## 四、结论

1. **A 是正解**：一次性、可枚举、可卸载；预置之后运行期在那些层级变成 `has_explicit_grant` 幂等跳过，86s 的重传播代价同时消失。
2. B 作为 A 的兜底（非 MSI 安装形态、或安装期被策略拒绝时使用），不单独作为方案。
3. C 是唯一「不碰盘根」的替代，但代价是删掉读隔离——不划算。
4. **不需要碰盘根**（2026-11-12 决定性实验）：`glob` 只 stat 盘根以下的字面层级，盘根写了没用。真正不可绕过的是工作区**中间层**（`C:\Users` 这类，`WRITE_DAC` 需管理员）；工作区在 `D:\...` 这种用户自有树下则整条链都免提权。把产物目录搬到容器自有目录只能解决 temp/构建缓存，解决不了工作区本身。（注意：**仅仅"路过"不需要 ACE**——详见 §二「遍历不是断点」；需要 ACE 的是「读属性/列举祖先本身」这件事。）
5. **已经排除的第四条（仅限 exec 路径）**：exec 时同步补祖先 ACE。实测 86s/次且对非提权无效，exec 路径上的调用已撤回（机制与降级审计保留）。**撤回的只是 exec 路径**：应用启动后的后台线程仍在补祖先 ACE（`lib.rs:3119-3120`、`mod.rs:531/627`，见 `docs/14`）；`grant_chain` 在生产代码中无调用点，唯一调用在测试。

## 五、本次范围

运行期机制（`ancestor_chain` / `grant_chain` / 降级审计 / 按深度还原）已实现并有用例，但**不在 exec 路径上调用**；A/B/C 均**未实施**，等待决策。后台线程会在应用启动后按持久口径补祖先 ACE（见 `docs/14`），这与「不在 exec 路径上调用」并不矛盾。

机制验证口径：`grant_chain_covers_ancestors_and_restores_them` 只在 `%TEMP%` 下自造三层链条（上界钉在临时根，**不向盘根写**），验证「可写祖先真的被加上 `Traverse`、没被升级成可列举、退出后按备份逐级还原」。反向对照已跑：去掉祖先段 → 该用例在「祖先应有 Traverse ACE」处变红；`Traverse` 放宽为 `FILE_GENERIC_READ | FILE_GENERIC_EXECUTE` → 在「不得升级成可列举/可读」处变红。

降级分支的端到端证据是真机审计（对 `C:\`、`C:\Users` 的写入被拒，`result:"denied"`，err 5），本机无法在可写层级内造出「`WRITE_DAC` 被拒且可恢复」的目录（给自己加 Deny 会连恢复一起锁死），该分支由 `degrade_only_for_ancestor_chain_and_access_denied` 的判定单测覆盖。
