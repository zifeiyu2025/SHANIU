> **SH-077 理由**：协议文档是前端与 AI 编码代理的唯一契约来源，**超前于实现的契约比没有契约更危险**——会让人按不存在的字段写代码，且编译/测试都拦不住（前端 TS 只在 IPC 边界做类型断言）。收口前共发现 12 处字段/字段集漂移（含 §1.1 信封未实现、审批事件字段集全不同、`ToolSpec` 签名多写 `risk`/`executor`、前端 `RiskLevel` 漏 `plan_review`），已按实现纠正或标注待实现里程碑。漂移清单本身**不入契约文档**：文档只表达"现在是什么样"，历史错处属工作过程产物，写进去会变成永不清理的包袱。本轮只动文档，待 code-reviewer 抽检。
> **SH-074 由来**：协议里 `tool_call_end` 只有 `exit_code` + `error`，前端只能按"无退出码 + 轮次 reason"反推取消（`src/store/reducers/turn.ts`），四态（ok/error/cancelled/denied）**根本不可区分**——审批拒绝与执行失败同徽标，同轮先失败后取消会被错归为取消，拒绝节点在该轮随后被取消时还会被抹成"已取消"。字段一经落地，反推逻辑必须收敛为直读 `result`。同批三条硬要求：① `ToolCallNode` 携带 `result`，轮次收敛**只在 `result === undefined` 时执行**（否则 `exit_code` 同为 null 的拒绝节点会被改写）；② 补前端 `RiskLevel` 缺失的 `plan_review` 变体，否则审批卡片按枚举分支渲染必然漏一个分支；③ `mock.ts` 同步发 `result`，否则 dev 模式永远走回退、字段等于没接线。视觉口径：`denied` 复用 `bg-line2 text-primary`，**不新增 warning 色**（主题层变更归 SH-041）。

> **SH-078 完成（2026-11-05）**：五个协议枚举（`TurnEndReason`/`IoChannel`/`RiskLevel`/`ApprovalDecision`/`ToolCallResult`）在 `events.rs` 各补 `all_variants()` 作为变体清单**单一事实源**，内部用无通配臂 match 做编译期穷举证明——加变体不更新清单 = 编译失败（E0004）。`event_schema.rs` 的硬编码清单全部改为消费这些函数；`EventMsg` 的 tag 清单（测试内 `all_variants()` vec）同样补编译期穷举，新增事件类型强制同步 `EXPECTED_TAGS`。受控探针双向复测：只加变体 → 编译失败；更新清单不改前端 → 测试红且报错指名 `types.ts` 缺 `'timeout'`。探针已还原，基线 110 用例复绿。**口径修正（评审阻塞项）**：FF-2 绿灯恢复为 **Rust→前端单向同步**的充分证据；TS 单方多出变体与 `EventMsg` 镜像 tag 仍需人工核对（`EXPECTED_TAGS` 未与 types.ts 机械绑定），补全归 SH-079。

> **SH-019 实测结论（2026-11-05）**：`RestrictedToken`（全特权删除）+ `JobObject` 可正常运行子进程，但**不提供路径级隔离**——受限令牌保留用户 SID，工作区内/外的普通文件 ACL 都照样放行。探针 `src-tauri/tests/sandbox_probe.rs::sandbox_denies_write_outside_workspace` 实测：越界写入退出码 0、文件落盘（该用例现以 `#[ignore]` 挂起，作为 SH-022 的验收探针）。
> 结论：FF-3 无法仅靠令牌达成。deny-ACE 需对工作区外**全部**路径持有 `WRITE_DAC`，普通用户权限不足，只能覆盖用户目录，会形成"部分隔离"的虚假安全感；Windows 上双向文件隔离的正解是 **AppContainer（SECURITY_CAPABILITIES）**，无需管理员权限。M2 按本条兜底条款降级为「逻辑沙箱 + 显式声明」，AppContainer 作为独立 ADR 进入 M3 评估，不在 M2 强推。

> SH-019 是硬骨头前移：RestrictedToken 沙箱是全套方案实现风险最高的部分，必须在 M1 验证可行性，不允许拖到 M2。SH-028 让 M2 之后的每次上下文工程变更（04 §6）都有客观回归度量。
