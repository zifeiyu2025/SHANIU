# SHANIU 协议规范

> 版本：v0.1｜日期：2026-11-05｜状态：活文档
> 本文档是前后端、工具系统、持久化的**唯一契约来源**。实现以此为准；schema 变更只允许 additive（新增 optional 字段/新增枚举变体），受健身函数 FF-104 与 `event_schema` 快照测试保护。
> 类型记法：Rust serde 语义。`?` = optional（`Option<T>` + `skip_serializing_if`）。

## 1. 事件协议（后端 → 前端）

### 1.1 信封

> 2026-11-06 定案：保留既有 `EventMsg` 载荷和命令签名，补齐会话信封；此前表内未实现的另一套字段名不作为适配层输入。TS 镜像位于 `src/transport/types.ts`，仅由 transport 消费，不修改 DSH 协议类型。

```rust
struct AgentEvent {
    event_id: String,          // 单调 ULID
    session_id: String,
    agent_id: String,          // 根代理为 "root"；子代理 ULID 待 M5
    parent_id: Option<String>, // root 明确序列化为 null
    ts_ms: u64,                // Unix 毫秒
    msg: EventMsg,             // 内部标签 serde(tag = "type", rename_all = "snake_case")
}
```

传输过渡期为 Tauri emit `shaniu://event`，载荷是上述信封；SH-094 切换 loopback WebSocket 时保持载荷不变。`msg` 内字段与 `type` 同层，**没有 `data` 子对象**。新信封类型不改变已有 EventMsg 变体与字段；广播由裸 EventMsg 切换为信封，接入方必须读取 `event.msg`，不保留双载荷通道。

当前根会话的 `session_id` 等于 `send_task` 返回的档案 ID（旧命令参数仍叫 `agent_id`），`agent_id` 固定为 `root`。新建及续写均绑定各自会话 ID；`event_id` 在同一进程内由共享单调生成器产生，编号与发送处于同一临界区，跨会话/续写不重置。`ts_ms` 是采集时钟，不代替 `event_id` 排序。**事件信封已逐条落盘**（SH-094 批 1）：广播出口在编号锁内先追加到 `<data_root>/sessions/<session_id>.events.jsonl` 再 emit，文件行序即 `event_id` 序；`read_session_events` 按 `after_event_id` 游标分页读回（只追加不改写，容忍崩溃半截尾行/中途坏行）。落盘失败只告警、不阻断广播。**gateway 断线续播接线在批 2/3**：当前传输仍是 Tauri emit，尚未把游标读回接到 WebSocket 重连，故暂不承诺跨重启的实时游标连续性。

### 1.2 EventMsg 枚举

| type | 与 type 同层的字段 | 语义 / 当前生产状态 |
| --- | --- | --- |
| `turn_started` | `{turn: u32}` | 一次模型采样迭代开始；同一用户任务内可多次产生，下一次用户任务从 1 重新计数 |
| `turn_completed` | `{turn: u32, reason: TurnEndReason}` | 整个用户任务结束，turn 为最后一次采样序号；不是每次 turn_started 都有一个对应结束事件 |
| `agent_message_delta` | `{delta: string}` | 助手正文增量 |
| `reasoning_delta` | `{delta: string}` | 思考增量，独立于正文 |
| `tool_call_begin` | `{call_id: string, tool: string, args: JSON}` | 工具调用开始；不含 risk，风险从审批请求取得 |
| `tool_call_output_delta` | `{call_id: string, channel: IoChannel, delta: string}` | stdout / stderr 增量；当前只由 unified_exec 产生 |
| `tool_call_end` | `{call_id: string, exit_code: i32|null, error: string|null, result?: ToolCallResult|null}` | 工具终态；result 非空时为唯一状态判据 |
| `exec_approval_request` | `{request_id: string, tool: string, args: JSON, risk: RiskLevel, agent_id?: string, task_summary?: string, reason?: string}` | 后端审批请求；裁决或取消前工具挂起。`agent_id`/`task_summary` 为 SH-054 新增的 additive 可选字段（FF-2）：标明是哪个代理、为哪项任务要权限；root 的 `agent_id` 为 `"root"`、无任务摘要。`reason` 为 SH-118⑤/SH-120 新增的 additive 可选字段：风险原因（如沙箱拒绝后的提权重试请求）。旧消费端忽略未知键即可 |
| `exec_approval_resolved` | `{request_id: string, decision: ApprovalDecision}` | 类型已定义，**生产端未发送**，待 SH-025 接线补齐 |
| `allowlist_hit` | `{tool: string, command: string, rule_id: string}` | SH-120 新增（additive）：命令前缀白名单命中即放行，`rule_id` 为 config.toml 中的规则原文；用于"不弹窗但必须留痕"的审计。旧消费端按未知类型忽略 |
| `plan_delta` | `{delta: string}` | 类型已定义，**生产端未发送** |
| `turn_diff` | `{files: string[]}` | 类型已定义，**生产端未发送**；不含补丁正文或 hunk 计数，SH-017 不得伪造 diff |
| `token_usage` | `{turn: u32, input_tokens: u32, cached_input_tokens?: u32|null, output_tokens: u32}` | 当次采样用量，不是累计值；缓存用量 None 序列化为 null |
| `error` | `{message: string}` | 错误说明，任务是否终结以 turn_completed 为准 |

`TurnEndReason = completed | cancelled | failed | budget_exhausted`；`IoChannel = stdout | stderr`；`RiskLevel = read | write_in_workspace | execute | destructive | plan_review`；`ApprovalDecision = allow | deny | allow_always`；`ToolCallResult = ok | error | cancelled | denied`。

#### 1.2.1 工具终态与关联

`result` 缺失或 null 时，消费端才允许按 exit_code / error 回退；不得根据错误文案猜测 denied。`result` 存在时即使 exit_code / error 与之冲突也不覆盖状态，但错误证据仍须展示。新增字段保持 optional，旧输入缺失与显式 null 均可反序列化。

`call_id` 来自模型，可能跨采样/用户任务复用，不能作为整份会话的永久节点 ID。适配层必须结合会话及调用发生次序建立节点身份，事件去重以信封 event_id 为准。审批按后端签发的 request_id 回执，不由前端生成授权 ID。

二期预留（M5，尚未进入当前 EventMsg）：`subagent_spawned {child_id, task, profile, allowed_tools}`、`subagent_exited {child_id, summary: ExitSummary}`、`subagent_message {child_id, direction, preview}`；direction 为 `to_child/from_child`。

### 1.4 loopback WebSocket gateway 线契约（SH-094 批 2）

> 2026-11-07 用户拍板「内部传输路线」：WS 只替换 **Rust → 适配层** 的事件传输（取代无背压的 Tauri 全局广播），投递的仍是 §1.1 的 `AgentEvent` 信封；适配层 → DSH 客户端继续走已实现的 DSH 原生 `session.follow/page`（seq 游标）。credit 背压与 `event_id` 续播是 SHANIU 内部传输特性——上游 DSH remote.mux **无** credit、重连发全量 snapshot 而非 after_event_id，故本协议不照搬上游，是 ADR-005 的自定取舍。

- **连接**：仅监听 `127.0.0.1`，动态端口（`TcpListener::bind("127.0.0.1:0")`），端口与 token 经控制面 `gateway_info` 命令回报。前端连 `ws://127.0.0.1:{port}`。一条连接按 `session_id` 多路复用所有会话。
- **帧格式**：JSON **text** 帧，字段 snake_case；binary 帧视为协议错（`error{protocol}` + 关闭）。Ping/Pong 由 tungstenite 自动应答。
- **鉴权**：连接后首帧必须是 `hello{token}`（5s 时限）；token 匹配回 `ready`，不匹配回 `error{unauthorized}` + 关闭。token = 进程级两个 ULID 拼接（160 bit CSPRNG 熵，URL 安全），非一次性（重连复用），非 API Key、不落日志。
- **C→S 帧**：
  - `{type:"hello", token}`
  - `{type:"subscribe", session_id, after_event_id?, credits?}` — 订阅一个会话；`credits`（默认 0）为初始信用窗口；`after_event_id` 省略 = **只接 live**（服务端用事件日志尾部初始化去重游标，绝不重放历史），带上则先从事件日志补该游标之后的信封再接 live。
  - `{type:"unsubscribe", session_id}`
  - `{type:"credit", session_id, credits}` — 追加信用（saturating_add）。
- **S→C 帧**：
  - `{type:"ready"}`
  - `{type:"event", event: AgentEvent}` — 仅发已订阅会话的信封，受 credit 闸门。
  - `{type:"error", code, message}` — `code` ∈ {`unauthorized`, `bad-request`, `protocol`, `overflow`}。
- **背压**：每会话独立 credit 计数，发一条减一；耗尽则排队等 `credit` 帧。出站队列硬上限 8192，溢出 fail-closed 回 `error{overflow}` + 关闭（客户端带 `after_event_id` 重连补帧）。续播本身也受队列上限约束：历史超长时先从日志补到队列上限，随 `credit` 腾出空间继续从 `last_id` 补，不跳号也不丢段。broadcast 通道容量 1024，消费端 lag 时从事件日志按各会话 `last_id` 补齐。
- **续播与去重**：`event_id` 单调（ULID 同宽字典序）；每会话记 `last_id`（末条入队 id），入队只收严格大于 `last_id` 者，故 replay 与 live 交叠不重发。续播读面复用批 1 `event_journal::read_after`（单页 ≤5000，分页直至 `has_more=false`）。
- **批 2/3 边界**：服务端已落地并随 app 启动（绑定失败只告警降级，事件仍走 Tauri 广播）；sink 落盘后经注入的 broadcast 发送端喂 hub。**批 3 已切换前端**（`src/transport/ws-bridge.ts`）：桌面事件面走 WS——订阅帧先于命令、按各会话 `lastEventId` 重连续播、credit 低水位补窗、打开会话视图即补订阅（`observeEvents`）；gateway 连续不可用时**一次性**退回 Tauri 广播，不双通道投递。`events` 模块只持 tokio `broadcast::Sender`（依赖倒置），不反向依赖 `gateway`（01 §2.3.1 E37）。

### 1.5 沙箱可见面（UI 契约，SH-021 补）

`unified_exec` 的隔离是「不静默降级」的另一半：**用户必须能随时看见自己跑在什么挡位里**。落位按 DSH 既有信息架构，不自造外壳：

| 可见面 | 槽位 | 作用域 | 内容 |
| --- | --- | --- | --- |
| 常驻状态条 | `shell.bottom` | root（单实例） | 沙箱挡位（`mode`）、OS 层（`os` / `osEnabled`）、容器 `profile`、当前网络授权会话列表、最近一次操作反馈（成功/失败）。**只展示，不提供授权动作**——root 作用域拿不到权威 `sessionId` |
| 网络开关 | `conversation.session.header.utilities` | 会话 | 「允许本会话联网 / 撤销」，`inject` 拿到的权威 `sessionId` 就是授权对象；撤销后两个可见面同时刷新 |

- **`retainedBy.mainView` 不可靠（实测结论）**：新建草稿时它仍指向**上一条历史会话**，用它在 root 作用域推断「当前会话」会把网络授权记到用户没在看的会话上——这是安全问题，不是体验问题。因此授权只允许走会话槽位的 `sessionId`；状态条里的授权列表只读。
- **视觉不可混淆**：logical 模式必须与 OS 沙箱态在视觉上可区分（警示底色 + 侧边色条 + 粗体警告），不能只靠一行小字。样式只用 `--dsw-alias-*` 令牌（light/dark 都存在的 alias；`theme-tokens.spec.ts` 机检），**禁止**使用上游不存在的 `--dsh-*` 变量。
- 授权/撤销失败必须回显给用户（含「后端本来就没有该授权」这种情况），不允许吞掉或假装成功。

#### 1.5.1 DACL 变更的时机与范围（SH-022 澄清，2026-11-08）

容器 SID 的写 ACE 是路径级隔离的唯一手段，但改安全描述符会惊动文件系统监听器（dev 下 Vite 会全量重载）。因此变更点必须可枚举、可复现：

**只碰这些目录**（`sandbox/acl.rs::write_scope`）：
1. 工作区根；
2. `TEMP` / `TMP` / `std::env::temp_dir()`（去重）；
3. 工具链目录：`CARGO_HOME` / `RUSTUP_HOME` / `PNPM_HOME` / `NPM_CONFIG_PREFIX`、`~/.cargo`、`~/.rustup`（只取存在的）。
- 只取**存在且是目录**的路径；被其他条目严格包含的路径**丢弃**（父目录的继承 ACE 已覆盖，不重复写）。

**真正会写 DACL 的只有两种情况**：
1. 本进程内某个工作区根下**首次**执行 workspace-write 命令，且该目录**缺**容器 SID 的显式 ACE → 先备份原始 DACL 到 `<data_root>/sandbox/acl/<hash>.dacl`，再写入；备份失败即拒绝执行（fail-closed）。
2. 退出时 / 下次启动的 `recover_pending` 按备份还原本进程写入过的 ACE；还原失败直接报错（不吞、不继续）。

**不会写 DACL 的情况**：
- 同一进程内重复 exec（每个工作区根只解析一次 scope；进程内已授权集合直接命中）；
- 磁盘上**已有**容器 SID 的显式 ACE（掩码覆盖读/写/执行/删除+删子项）→ 视为外部授权，跳过改写、不写备份、退出也不撤销（避免误删同时运行的另一个实例正在用的授权）；
- read-only 策略（直接拒绝，不起容器）、danger-full-access、`sandbox.os = "logical"`。

**代价声明**：上述第 1 条在每次进程启动后、每个工作区根上**最多各发生一次** DACL 写入。生产环境没有 Vite，但索引器/文件监听型工具链仍可能因此收到一次通知；这是接受的一次性代价，换来的是"改安全描述符只在缺 ACE 时发生"，而不是每次 exec 都碰工作区根。

**todo_write 的数据面契约**（SH-108，对齐上游 `packages/todo/tool-todo`）：不新增 `EventMsg` 变体、不写 rollout 新条目——SHANIU 的持久化事实源是模型历史，工具调用记录本身就在档案里；适配层从「调用参数 + 执行结果」在实时与回放两条路径推导 journal `todo/write` 事件（`{todos: [{content, status}]}`，content 为 trim 后值）并折叠成 `todos` 投影（fold 语义照上游：todo/write 整表替换、turn/start 清空、turn/end 保留）。推导的可信判据：实时 = `ToolCallResult::ok`；回放 = 调用留有结果文本且参数通过适配层镜像的后端校验谓词（trim 非空/判重/三态枚举/条目仅 content+status 两键）。偏差声明：① 工具描述按 §6.2 收敛为 ≤200 字符的紧凑英文（语义保留上游三段式指引），不逐字抄上游 350 字符文案——实测每请求多扛 ~220 token 声明开销，触发 §6.5 的 token 门禁；schema、校验语义与输出文案仍与上游对齐；② 校验拒绝走 `InvalidArgs`（档案输出无 exit 标记），与既有工具约定一致。部署口径 `allow_parallel_in_progress = true`（上游 base bundle 默认）。

**工具不变量**：① 任何 write/execute/destructive 工具的执行路径必经 permission broker，无后门（FF：approval_contract）；② 工具输出进入模型上下文前统一截断与编码；③ MCP 输出外层包裹不可信标记。

**模型清单与生效档的一致性**：`models` 非空且 `model` 非空时，`model` 必须是 `models` 里的一行（`save_providers` 与 `save_settings` 两个写入口都校验）。理由是可见的：席位下拉只列 `models`，生效档不在清单里就意味着"跑着一个选不出来的模型"，用户随手点一下别的行就把档位换掉而不自知。`save_settings` 改生效模型时也要拦——它走 `update_config`，不经过 `save_providers` 的校验，漏一步就能写出这种文档。

**字段名的大小写**：命令返回值用 camelCase（`baseUrl` / `secretRef` / `contextWindow`），`config.toml` 落盘用 snake_case（`base_url` / `secret_ref` / `context_window`），`ProviderProfile` / `ModelProfile` 用 `#[serde(alias)]` 让 JSON 侧两种写法都接受。alias 不是风格照顾：serde 对结构体字段**不做**命名转换，认不到的键会被容器级 `#[serde(default)]` 静默填成缺省值，前端送 `baseUrl` 而字段只认 `base_url` 的话，写进去的就是一个空端点而不是报错。

## 6. 上下文工程（Context Engineering）

> 本章是 Agent 行为质量的核心契约。turn 循环的骨架在 01/02 文档，但 Agent 好不好用主要取决于本章内容。本章内容以代码形式落地于 `agent_loop/prompts/`，**任何变更必须附评估基线回归结果**（05 SH-028/073）。

### 6.1 系统提示结构（固定顺序）

```
1. 身份与目标        # SHANIU 编码代理，一句话使命
2. 环境声明          # OS=Windows、shell=PowerShell、工作区路径、沙箱模式、当前时间
3. 行为准则          # 简短命令式条款：先读后改 / 小步提交 / 不确定就问 / 禁止臆造 API
4. 工具使用规范      # 工具选择优先级（apply_patch 优先于 shell 写入）、并行调用规则
5. 沙箱与审批说明    # 当前模式下哪些操作会触发审批，被拒绝后如何调整策略
6. 输出规范          # 面向终端的简洁汇报格式，禁止寒暄与重复用户输入
```

**不变量**：① 总长度 ≤ 2K tokens；② 条款为命令式短句，每条一行；③ 环境声明每轮动态注入（沙箱模式变化必须反映）；④ 禁止在系统提示中写示例对话（few-shot 放用户轮）。

### 6.2 工具描述规范

- `description` ≤ 200 字符，首句说"做什么"，次句说"何时用/不用"。
- 参数描述必须含约束（如 `timeout_ms` 的默认值与上限），禁止只写类型名。
- 高风险工具（execute/destructive）描述中显式声明会触发审批，降低模型被拒后的"意外感"。

### 6.3 错误回填格式（工具结果 → 模型）

```
<tool_result name="..." status="error|denied|cancelled">
  <error_code>PATH_OUTSIDE_WORKSPACE</error_code>
  <message>人类可读本机语言一句话</message>
  <suggestion>可执行的下一步建议（如：改用工作区内路径，或请求用户授权）</suggestion>
</tool_result>
```

**不变量**：① `error_code` 为枚举（见 `agent_loop/error_codes.rs`），禁止自由文本当 code；② `denied`（用户拒绝）与 `error`（执行失败）严格区分——被拒绝后模型应换策略而非重试；③ MCP 工具结果外层再包 `<untrusted_content>` 标记；④ 输出截断时标注 `truncated: true` 与原始大小。

### 6.4 Compaction 摘要格式

压缩总结必须保留的固定字段：`任务目标 / 已完成事项 / 关键文件与改动 / 未解决问题 / 下一步`。摘要写回 rollout 为 `Compacted` 项，resume 时据此重建。

### 6.5 评估基线挂钩

- 基线任务集与评分脚本位于 `evals/`（SH-028 建立 v0，SH-073 扩展至全集）。
- **判定的分母是「当日对照」，不是冻结基线**：每次评估当天先跑对照臂 `SHANIU_EVAL_ROLE=control SHANIU_EVAL_ABLATE_AR6=1`（≥5 次，`evals/control.json`），再跑实验臂（默认，`evals/latest.json`）。判定只在**同日、同端点、同模型、同参数（任务集/轮数上限/重复次数）**的两组之间做；任一不一致 `score.mjs` 直接拒绝下结论（exit 2）。
- **固定步骤（顺序不可换；跳过任何一步都得不到结论）**：
  1. 固定端点与模型（`SHANIU_TEST_BASE_URL` / `SHANIU_TEST_MODEL`），当天不再更换；
  2. 对照臂：`SHANIU_EVAL_REPEATS=5 SHANIU_EVAL_ROLE=control SHANIU_EVAL_ABLATE_AR6=1` → `evals/control.json`；
  3. 实验臂：`SHANIU_EVAL_REPEATS=5 SHANIU_EVAL_ROLE=treatment`（不设 `SHANIU_EVAL_ABLATE_AR6`）→ `evals/latest.json`；
  4. `node evals/score.mjs`。缺任一臂、跨日、端点半途更换、任务集或参数不一致 → **exit 2**，不得手改报告或换分母凑结论。
  只跑实验臂等于没有分母：`score.mjs` 在 `control.json` 缺失或样本 < 5 时直接拒绝；**禁止**用冻结基线临时充当对照。
- **冻结基线（`evals/baseline.<model>.json`）只作历史参考，不参与判定**。失效原因：实测端点漂移把整份基线整体上抬 32%/轮，跨日的冻结点已经不是同一把尺子，拿它当分母结论永远红且没有信息量。跨日对比无效是**已知事实**，不是待验证假设。
- 触发回归评估的变更：系统提示、工具描述、错误回填格式、compaction 逻辑、编排工具。
- 指标退化 >10% 阻断合并（AGENTS.md §5）。
- **判定样本必须是多次运行的中位数（≥5 次，`SHANIU_EVAL_REPEATS` 默认 5）**：单次运行不足以区分「能力退化」与「端点抖动」。两臂报告都保留每次运行的数字（含变红的那些）与中位数，禁止只留最好的一次。
- **成功率下降是硬否决**；`avg_turns` / `avg_total_tokens` 只在「中位数相对对照越阈 **且每次运行都越阈**」时才判红，否则记为观察项。
- 阈值不得为了「凑绿」而下调；要改只改「怎么得出结论」的方法（样本数、中位数、对照臂、一致性规则）。
- `SHANIU_EVAL_ABLATE_AR6=1` 是**评估消融开关**，只用于关掉系统提示里的「不可信工具输出」条款做对照；它不写进设置、不随会话持久化、默认不生效，输出包裹标记不受影响。
