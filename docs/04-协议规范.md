# SHANIU 协议规范

> 版本：v0.1｜日期：2026-11-05｜状态：活文档
> 本文档是前后端、工具系统、持久化的**唯一契约来源**。实现以此为准；schema 变更只允许 additive（新增 optional 字段/新增枚举变体），受健身函数 FF-104 与 `event_schema` 快照测试保护。
> 类型记法：Rust serde 语义。`?` = optional（`Option<T>` + `skip_serializing_if`）。

---

## 1. 事件协议（后端 → 前端）

### 1.1 信封

```rust
/// 传输：loopback WebSocket gateway（ADR-005 修订，SH-094）；切换前过渡为 Tauri emit "shaniu://event"。
/// 载荷与结构不随传输变化。
struct AgentEvent {
    event_id: String,        // ULID，单调递增，用于去重与断线对齐
    session_id: String,
    agent_id: String,        // "root" 或子代理 ULID
    parent_id: Option<String>, // root 为 null
    ts_ms: u64,
    msg: EventMsg,           // serde(tag = "type", content = "data")
}
```

### 1.2 EventMsg 枚举

| type | data 字段 | 说明 | 引入 |
| --- | --- | --- | --- |
| `turn_started` | `{turn_id, input_preview}` | 一轮任务开始 | v1 |
| `agent_message_delta` | `{turn_id, delta}` | 模型输出流式增量（追加渲染） | v1 |
| `tool_call_begin` | `{call_id, tool, args, risk}` | 工具调用开始；risk ∈ `read/write/execute/destructive` | v1 |
| `tool_call_output_delta` | `{call_id, stream, delta}` | 工具输出增量；stream ∈ `stdout/stderr/result` | v1 |
| `tool_call_end` | `{call_id, status, duration_ms}` | status ∈ `ok/error/cancelled/denied` | v1 |
| `exec_approval_request` | `{approval_id, call_id, risk, summary, detail}` | 审批请求；裁决前工具挂起 | v1 |
| `exec_approval_resolved` | `{approval_id, decision, remember}` | 审批结果回执（decision ∈ `allow/deny`） | v1 |
| `plan_delta` | `{delta}` | Plan Mode 计划内容增量 | v1 |
| `turn_diff` | `{files: [{path, hunks_added, hunks_removed}]}` | 本轮文件变更汇总 | v1 |
| `token_usage` | `{turn_id, input, output, cumulative}` | token 用量 | v1 |
| `turn_completed` | `{turn_id, status, reason?}` | status ∈ `done/error/cancelled/budget_exceeded` | v1 |
| `error` | `{code, message, recoverable}` | 全局错误 | v1 |
| `subagent_spawned` | `{child_id, task, profile, allowed_tools}` | 子代理创建 | v2 |
| `subagent_exited` | `{child_id, summary: ExitSummary}` | 子代理退出 | v2 |
| `subagent_message` | `{child_id, direction, preview}` | 父子间消息；direction ∈ `to_child/from_child` | v2 |

### 1.3 命令（前端 → 后端，Tauri invoke）

| command | 参数 | 返回 | 说明 |
| --- | --- | --- | --- |
| `send_task` | `{session_id?, text, attachments?}` | `{session_id, turn_id}` | 提交任务；无 session_id 则新建 |
| `approve` | `{approval_id, decision, remember}` | `()` | 审批回执；approval_id 由后端签发并校验，伪造/过期一律拒绝 |
| `cancel` | `{session_id}` | `()` | 取消整棵任务树（级联） |
| `steer_agent` | `{agent_id, text}` | `()` | 向指定代理注入 steering |
| `list_sessions` / `resume_session` / `fork_session` | `{session_id, ...}` | 会话元数据 | rollout 恢复 |
| `get_config` / `set_config` | `{patch}` | 配置对象 | 热更新，写 settings-backup |
| `set_mode` | `{session_id, mode}` | `()` | mode ∈ `normal/plan`；ExitPlanMode 必须经审批通道 |

**协议不变量**：① 同一 `turn_id` 内事件按 `event_id` 全序；② `tool_call_begin` 必有配对 `tool_call_end`（含 cancelled/denied）；③ `exec_approval_request` 未 resolve 前对应 call 不产生 `tool_call_end`；④ 前端重连后按 `event_id` 续播，缺口从 rollout 补齐。

## 2. 工具协议（ToolSpec）

统一签名：`ToolSpec { name, description, json_schema, risk, executor }`。模型可见性按当前代理 depth/profile 过滤。

| name | risk | 关键参数 | 返回要点 | 可见性 |
| --- | --- | --- | --- | --- |
| `unified_exec` | execute | `{cmd, cwd?, timeout_ms?, stdin?}` | 流式 stdout/stderr + exit_code | 全部 |
| `apply_patch` | write | `{patch}`（结构化 diff，禁止绝对路径越界） | `{applied[], rejected[]}`；dry-run 先行 | 全部 |
| `read_file` / `list_dir` / `search` | read | `{path/pattern, ...}` | 内容（超 64KB 截断+标注） | 全部 |
| `plan` | read | `{action: enter/exit, plan?}` | exit 必须用户确认后生效 | 全部 |
| `request_user_input` | read | `{question, options?}` | 用户答复 | 全部 |
| `spawn_agent` | write | `{task, profile?, budget_tokens?, allowed_tools?}` | `{agent_id}` | 仅 depth=0 |
| `resume_agent` | write | `{agent_id, instruction?}` | `()` | 仅 depth=0 |
| `wait_agent` | read | `{agent_ids[], timeout_ms}` | `[ExitSummary]`（部分超时） | 仅 depth=0 |
| `send_agent_message` | write | `{agent_id, text}` | 应答摘要 | 仅 depth=0 |
| `terminal` | execute | `{action: open/write/read/close, session_id?, data?}` | PTY 输出流 | 全部 |
| `mcp__<server>__<tool>` | 按声明映射 | server 提供 schema | 输出按不可信内容包裹 | 按信任级 |

`ExitSummary = {status: done/failed/cancelled, summary: String /*≤4KB*/, artifacts: String[], token_usage: {input, output}}`

**工具不变量**：① 任何 write/execute/destructive 工具的执行路径必经 permission broker，无后门（FF：approval_contract）；② 工具输出进入模型上下文前统一截断与编码；③ MCP 输出外层包裹不可信标记。

## 3. 持久化格式

### 3.1 rollout（`rollouts/<agent_id>.jsonl`，一行一个 RolloutItem）

| variant | 内容 | 说明 |
| --- | --- | --- |
| `SessionMeta` | `{session_id, agent_id, parent_id, created_at, config_snapshot}` | 文件首行，必须存在 |
| `ResponseItem` | 模型请求/响应/工具调用的完整记录 | 主体，顺序与 event_id 对齐 |
| `Compacted` | `{range, summary}` | 压缩锚点，resume 时替换区间 |
| `SubagentRef` | `{child_id, rollout_path}` | 父文件中的子代理引用 |

fork = 复制文件截断到指定 event_id + 新 SessionMeta；resume = 重放至尾部后继续追加。

### 3.2 会话索引（`sessions/<session_id>.json`）

`{session_id, title, created_at, updated_at, root_rollout, agents: [{agent_id, rollout_path, status}], token_usage_total}`

## 6. 上下文工程（Context Engineering）

> 本章是 Agent 行为质量的核心契约。turn 循环的骨架在 01/02 文档，但 Agent 好不好用主要取决于本章内容。本章内容以代码形式落地于 `agent_loop/prompts/`，**任何变更必须附评估基线回归结果**（05 SH-028/073）。

### 6.1 系统提示结构（固定顺序）

```
1. 身份与目标        # SHANIU 编码代理，一句话使命
2. 环境声明          # OS=Windows、shell=PowerShell、工作区路径、沙箱模式、当前时间
3. 行为准则          # 简短命令式条款：先读后改 / 小步提交 / 不确定就问 / 禁止臆造 API
4. 工具使用规范      # 工具选择优先级（apply_patch 优先于 shell 写入）、并行调用规则
5. 沙箱与审批说明    # 当前模式下哪些操作会触发审批，被拒绝后如何调整策略
6. 输出规范          # 面向终端的简洁汇报格式，禁止寒暄与重复用户输入
```

**不变量**：① 总长度 ≤ 2K tokens；② 条款为命令式短句，每条一行；③ 环境声明每轮动态注入（沙箱模式变化必须反映）；④ 禁止在系统提示中写示例对话（few-shot 放用户轮）。

### 6.2 工具描述规范

- `description` ≤ 200 字符，首句说"做什么"，次句说"何时用/不用"。
- 参数描述必须含约束（如 `timeout_ms` 的默认值与上限），禁止只写类型名。
- 高风险工具（execute/destructive）描述中显式声明会触发审批，降低模型被拒后的"意外感"。

### 6.3 错误回填格式（工具结果 → 模型）

```
<tool_result name="..." status="error|denied|cancelled">
  <error_code>PATH_OUTSIDE_WORKSPACE</error_code>
  <message>人类可读本机语言一句话</message>
  <suggestion>可执行的下一步建议（如：改用工作区内路径，或请求用户授权）</suggestion>
</tool_result>
```

**不变量**：① `error_code` 为枚举（见 `agent_loop/error_codes.rs`），禁止自由文本当 code；② `denied`（用户拒绝）与 `error`（执行失败）严格区分——被拒绝后模型应换策略而非重试；③ MCP 工具结果外层再包 `<untrusted_content>` 标记；④ 输出截断时标注 `truncated: true` 与原始大小。

### 6.4 Compaction 摘要格式

压缩总结必须保留的固定字段：`任务目标 / 已完成事项 / 关键文件与改动 / 未解决问题 / 下一步`。摘要写回 rollout 为 `Compacted` 项，resume 时据此重建。

### 6.5 评估基线挂钩

- 基线任务集与评分脚本位于 `evals/`（SH-028 建立 v0，SH-073 扩展至全集）。
- 触发回归评估的变更：系统提示、工具描述、错误回填格式、compaction 逻辑、编排工具。
- 指标退化 >10% 阻断合并（AGENTS.md §5）。

## 7. 版本与兼容

- 协议版本随文档：`v1`（01 文档 M0–M4）、`v2`（02 文档新增 3 个事件 + orchestrate 工具）。
- 前端启动时与后端握手 `protocol_version`；主版本不一致拒绝连接并提示升级。
- 任何 breaking 变更 = 新主版本 + 新文档章节，禁止原地修改既有 variant 字段语义。
