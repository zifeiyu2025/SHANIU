# SHANIU 协议规范

> 版本：v0.1｜日期：2026-11-05｜状态：活文档
> 本文档是前后端、工具系统、持久化的**唯一契约来源**。实现以此为准；schema 变更只允许 additive（新增 optional 字段/新增枚举变体），受健身函数 FF-104 与 `event_schema` 快照测试保护。
> 类型记法：Rust serde 语义。`?` = optional（`Option<T>` + `skip_serializing_if`）。

## 1. 事件协议（后端 → 前端）

### 1.1 信封

> 2026-11-06 定案：保留既有 `EventMsg` 载荷和命令签名，补齐会话信封；此前表内未实现的另一套字段名不作为适配层输入。TS 镜像位于 `src/transport/types.ts`，仅由 transport 消费，不修改 DSH 协议类型。

```rust
struct AgentEvent {
    event_id: String,          // 单调 ULID
    session_id: String,
    agent_id: String,          // 根代理为 "root"；子代理 ULID 待 M5
    parent_id: Option<String>, // root 明确序列化为 null
    ts_ms: u64,                // Unix 毫秒
    msg: EventMsg,             // 内部标签 serde(tag = "type", rename_all = "snake_case")
}
```

传输过渡期为 Tauri emit `shaniu://event`，载荷是上述信封；SH-094 切换 loopback WebSocket 时保持载荷不变。`msg` 内字段与 `type` 同层，**没有 `data` 子对象**。新信封类型不改变已有 EventMsg 变体与字段；广播由裸 EventMsg 切换为信封，接入方必须读取 `event.msg`，不保留双载荷通道。

当前根会话的 `session_id` 等于 `send_task` 返回的档案 ID（旧命令参数仍叫 `agent_id`），`agent_id` 固定为 `root`。新建及续写均绑定各自会话 ID；`event_id` 在同一进程内由共享单调生成器产生，编号与发送处于同一临界区，跨会话/续写不重置。`ts_ms` 是采集时钟，不代替 `event_id` 排序。**事件信封已逐条落盘**（SH-094 批 1）：广播出口在编号锁内先追加到 `<data_root>/sessions/<session_id>.events.jsonl` 再 emit，文件行序即 `event_id` 序；`read_session_events` 按 `after_event_id` 游标分页读回（只追加不改写，容忍崩溃半截尾行/中途坏行）。落盘失败只告警、不阻断广播。**gateway 断线续播接线在批 2/3**：当前传输仍是 Tauri emit，尚未把游标读回接到 WebSocket 重连，故暂不承诺跨重启的实时游标连续性。

### 1.2 EventMsg 枚举

| type | 与 type 同层的字段 | 语义 / 当前生产状态 |
| --- | --- | --- |
| `turn_started` | `{turn: u32}` | 一次模型采样迭代开始；同一用户任务内可多次产生，下一次用户任务从 1 重新计数 |
| `turn_completed` | `{turn: u32, reason: TurnEndReason}` | 整个用户任务结束，turn 为最后一次采样序号；不是每次 turn_started 都有一个对应结束事件 |
| `agent_message_delta` | `{delta: string}` | 助手正文增量 |
| `reasoning_delta` | `{delta: string}` | 思考增量，独立于正文 |
| `tool_call_begin` | `{call_id: string, tool: string, args: JSON}` | 工具调用开始；不含 risk，风险从审批请求取得 |
| `tool_call_output_delta` | `{call_id: string, channel: IoChannel, delta: string}` | stdout / stderr 增量；当前只由 unified_exec 产生 |
| `tool_call_end` | `{call_id: string, exit_code: i32|null, error: string|null, result?: ToolCallResult|null}` | 工具终态；result 非空时为唯一状态判据 |
| `exec_approval_request` | `{request_id: string, tool: string, args: JSON, risk: RiskLevel, agent_id?: string, task_summary?: string, reason?: string}` | 后端审批请求；裁决或取消前工具挂起。`agent_id`/`task_summary` 为 SH-054 新增的 additive 可选字段（FF-2）：标明是哪个代理、为哪项任务要权限；root 的 `agent_id` 为 `"root"`、无任务摘要。`reason` 为 SH-118⑤/SH-120 新增的 additive 可选字段：风险原因（如沙箱拒绝后的提权重试请求）。旧消费端忽略未知键即可 |
| `exec_approval_resolved` | `{request_id: string, decision: ApprovalDecision}` | 类型已定义，**生产端未发送**，待 SH-025 接线补齐 |
| `allowlist_hit` | `{tool: string, command: string, rule_id: string}` | SH-120 新增（additive）：命令前缀白名单命中即放行，`rule_id` 为 config.toml 中的规则原文；用于"不弹窗但必须留痕"的审计。旧消费端按未知类型忽略 |
| `plan_delta` | `{delta: string}` | 类型已定义，**生产端未发送** |
| `turn_diff` | `{files: string[]}` | 类型已定义，**生产端未发送**；不含补丁正文或 hunk 计数，SH-017 不得伪造 diff |
| `token_usage` | `{turn: u32, input_tokens: u32, cached_input_tokens?: u32|null, output_tokens: u32}` | 当次采样用量，不是累计值；缓存用量 None 序列化为 null |
| `error` | `{message: string}` | 错误说明，任务是否终结以 turn_completed 为准 |

`TurnEndReason = completed | cancelled | failed | budget_exhausted`；`IoChannel = stdout | stderr`；`RiskLevel = read | write_in_workspace | execute | destructive | plan_review`；`ApprovalDecision = allow | deny | allow_always`；`ToolCallResult = ok | error | cancelled | denied`。

#### 1.2.1 工具终态与关联

`result` 缺失或 null 时，消费端才允许按 exit_code / error 回退；不得根据错误文案猜测 denied。`result` 存在时即使 exit_code / error 与之冲突也不覆盖状态，但错误证据仍须展示。新增字段保持 optional，旧输入缺失与显式 null 均可反序列化。

`call_id` 来自模型，可能跨采样/用户任务复用，不能作为整份会话的永久节点 ID。适配层必须结合会话及调用发生次序建立节点身份，事件去重以信封 event_id 为准。审批按后端签发的 request_id 回执，不由前端生成授权 ID。

二期预留（M5，尚未进入当前 EventMsg）：`subagent_spawned {child_id, task, profile, allowed_tools}`、`subagent_exited {child_id, summary: ExitSummary}`、`subagent_message {child_id, direction, preview}`；direction 为 `to_child/from_child`。

### 1.4 loopback WebSocket gateway 线契约（SH-094 批 2）

> 2026-11-07 用户拍板「内部传输路线」：WS 只替换 **Rust → 适配层** 的事件传输（取代无背压的 Tauri 全局广播），投递的仍是 §1.1 的 `AgentEvent` 信封；适配层 → DSH 客户端继续走已实现的 DSH 原生 `session.follow/page`（seq 游标）。credit 背压与 `event_id` 续播是 SHANIU 内部传输特性——上游 DSH remote.mux **无** credit、重连发全量 snapshot 而非 after_event_id，故本协议不照搬上游，是 ADR-005 的自定取舍。

- **连接**：仅监听 `127.0.0.1`，动态端口（`TcpListener::bind("127.0.0.1:0")`），端口与 token 经控制面 `gateway_info` 命令回报。前端连 `ws://127.0.0.1:{port}`。一条连接按 `session_id` 多路复用所有会话。
- **帧格式**：JSON **text** 帧，字段 snake_case；binary 帧视为协议错（`error{protocol}` + 关闭）。Ping/Pong 由 tungstenite 自动应答。
- **鉴权**：连接后首帧必须是 `hello{token}`（5s 时限）；token 匹配回 `ready`，不匹配回 `error{unauthorized}` + 关闭。token = 进程级两个 ULID 拼接（160 bit CSPRNG 熵，URL 安全），非一次性（重连复用），非 API Key、不落日志。
- **C→S 帧**：
  - `{type:"hello", token}`
  - `{type:"subscribe", session_id, after_event_id?, credits?}` — 订阅一个会话；`credits`（默认 0）为初始信用窗口；`after_event_id` 省略 = **只接 live**（服务端用事件日志尾部初始化去重游标，绝不重放历史），带上则先从事件日志补该游标之后的信封再接 live。
  - `{type:"unsubscribe", session_id}`
  - `{type:"credit", session_id, credits}` — 追加信用（saturating_add）。
- **S→C 帧**：
  - `{type:"ready"}`
  - `{type:"event", event: AgentEvent}` — 仅发已订阅会话的信封，受 credit 闸门。
  - `{type:"error", code, message}` — `code` ∈ {`unauthorized`, `bad-request`, `protocol`, `overflow`}。
- **背压**：每会话独立 credit 计数，发一条减一；耗尽则排队等 `credit` 帧。出站队列硬上限 8192，溢出 fail-closed 回 `error{overflow}` + 关闭（客户端带 `after_event_id` 重连补帧）。续播本身也受队列上限约束：历史超长时先从日志补到队列上限，随 `credit` 腾出空间继续从 `last_id` 补，不跳号也不丢段。broadcast 通道容量 1024，消费端 lag 时从事件日志按各会话 `last_id` 补齐。
- **续播与去重**：`event_id` 单调（ULID 同宽字典序）；每会话记 `last_id`（末条入队 id），入队只收严格大于 `last_id` 者，故 replay 与 live 交叠不重发。续播读面复用批 1 `event_journal::read_after`（单页 ≤5000，分页直至 `has_more=false`）。
- **批 2/3 边界**：服务端已落地并随 app 启动（绑定失败只告警降级，事件仍走 Tauri 广播）；sink 落盘后经注入的 broadcast 发送端喂 hub。**批 3 已切换前端**（`src/transport/ws-bridge.ts`）：桌面事件面走 WS——订阅帧先于命令、按各会话 `lastEventId` 重连续播、credit 低水位补窗、打开会话视图即补订阅（`observeEvents`）；gateway 连续不可用时**一次性**退回 Tauri 广播，不双通道投递。`events` 模块只持 tokio `broadcast::Sender`（依赖倒置），不反向依赖 `gateway`（01 §2.3.1 E37）。

### 1.5 沙箱可见面（UI 契约，SH-021 补）

`unified_exec` 的隔离是「不静默降级」的另一半：**用户必须能随时看见自己跑在什么挡位里**。落位按 DSH 既有信息架构，不自造外壳：

| 可见面 | 槽位 | 作用域 | 内容 |
| --- | --- | --- | --- |
| 常驻状态条 | `shell.bottom` | root（单实例） | 沙箱挡位（`mode`）、OS 层（`os` / `osEnabled`）、容器 `profile`、当前网络授权会话列表、最近一次操作反馈（成功/失败）。**只展示，不提供授权动作**——root 作用域拿不到权威 `sessionId` |
| 网络开关 | `conversation.session.header.utilities` | 会话 | 「允许本会话联网 / 撤销」，`inject` 拿到的权威 `sessionId` 就是授权对象；撤销后两个可见面同时刷新 |

- **`retainedBy.mainView` 不可靠（实测结论）**：新建草稿时它仍指向**上一条历史会话**，用它在 root 作用域推断「当前会话」会把网络授权记到用户没在看的会话上——这是安全问题，不是体验问题。因此授权只允许走会话槽位的 `sessionId`；状态条里的授权列表只读。
- **视觉不可混淆**：logical 模式必须与 OS 沙箱态在视觉上可区分（警示底色 + 侧边色条 + 粗体警告），不能只靠一行小字。样式只用 `--dsw-alias-*` 令牌（light/dark 都存在的 alias；`theme-tokens.spec.ts` 机检），**禁止**使用上游不存在的 `--dsh-*` 变量。
- 授权/撤销失败必须回显给用户（含「后端本来就没有该授权」这种情况），不允许吞掉或假装成功。

#### 1.5.1 DACL 变更的时机与范围（SH-022 澄清，2026-11-08）

容器 SID 的写 ACE 是路径级隔离的唯一手段，但改安全描述符会惊动文件系统监听器（dev 下 Vite 会全量重载）。因此变更点必须可枚举、可复现：

**只碰这些目录**（`sandbox/acl.rs::write_scope`）：
1. 工作区根；
2. `TEMP` / `TMP` / `std::env::temp_dir()`（去重）；
3. 工具链目录：`CARGO_HOME` / `RUSTUP_HOME` / `PNPM_HOME` / `NPM_CONFIG_PREFIX`、`~/.cargo`、`~/.rustup`（只取存在的）。
- 只取**存在且是目录**的路径；被其他条目严格包含的路径**丢弃**（父目录的继承 ACE 已覆盖，不重复写）。

**真正会写 DACL 的只有两种情况**：
1. 本进程内某个工作区根下**首次**执行 workspace-write 命令，且该目录**缺**容器 SID 的显式 ACE → 先备份原始 DACL 到 `<data_root>/sandbox/acl/<hash>.dacl`，再写入；备份失败即拒绝执行（fail-closed）。
2. 退出时 / 下次启动的 `recover_pending` 按备份还原本进程写入过的 ACE；还原失败直接报错（不吞、不继续）。

**不会写 DACL 的情况**：
- 同一进程内重复 exec（每个工作区根只解析一次 scope；进程内已授权集合直接命中）；
- 磁盘上**已有**容器 SID 的显式 ACE（掩码覆盖读/写/执行/删除+删子项）→ 视为外部授权，跳过改写、不写备份、退出也不撤销（避免误删同时运行的另一个实例正在用的授权）；
- read-only 策略（直接拒绝，不起容器）、danger-full-access、`sandbox.os = "logical"`。

**代价声明**：上述第 1 条在每次进程启动后、每个工作区根上**最多各发生一次** DACL 写入。生产环境没有 Vite，但索引器/文件监听型工具链仍可能因此收到一次通知；这是接受的一次性代价，换来的是"改安全描述符只在缺 ACE 时发生"，而不是每次 exec 都碰工作区根。

| `output` | `{id, data}` | PTY 输出增量（UTF-8 增量解码后的字符串，跨块断字符已处理） |
| `exit` | `{id, code}` | 子进程退出；`code` 在无退出码时取 `-1` |

另有一条**提示**通道 `user-terminal://tray-hint`，载荷 `{count}`：仅在 main 窗口收到
`CloseRequested`（隐藏到托盘）且 `count > 0` 时**发一次**，由前端渲染一次性 toast
（不弹模态、不重试、不轮询）。它不携带终端内容，也不属于会话事件；没有存活会话时
不发，避免每次关窗都制造噪音。

**这不是 `EventMsg`**（§1.2），不进 `shaniu://event`，不落 `sessions/<id>.events.jsonl`，不参与 gateway 续播与 `last_id` 去重。

#### 1.6.3 三条边界（结构性保证，不是调用约定）

1. **不进沙箱**：`user_terminal::pty` 是自包含的 ConPTY 原语，**刻意不 import `sandbox/windows_impl`**——不建受限令牌、不挂 AppContainer、不经审批 broker。理由：沙箱约束的是不可信执行者（模型），用户本人本来就有整机权限；关进容器只会让自敲命令被无名拒绝，安全收益为零。若将来 ConPTY 与容器不兼容，只能显式拒绝该能力并在 UI 说明，**禁止**提权绕过。
2. **不进模型上下文**：用户敲的命令、终端输出、cwd 变化一律不进 history、不进采样请求、不写 rollout。结构上没有数据路径——模块内不构造任何 `EventMsg`、不触 `rollout` / `event_journal` / `unified_exec` / `TauriEventSink`。由 `user_terminal::tests::module_never_touches_model_context`（扫生产代码禁用标识符）与 `src/terminal-source/index.spec.ts`（命令序列只含 `user_terminal_*`、只订阅专用通道）两侧钉住，**不是只写在注释里**。
3. **不走 `unified_exec`**：每标签一个独立进程 + 独立 Job，不共享 agent 的执行通道，也不出现在 agent 的工具调用记录里。

#### 1.6.4 进程回收

每个 PTY 子进程挂在一个 Job Object 上，`JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`：Job 句柄关闭（正常 `close`、应用退出、进程崩溃）时由内核回收**整棵进程树**，不留孤儿。前端 `beforeunload` 追加一次 `user_terminal_close_all` 作为正常退出的快速路径。

**证据形态**：真机 `tasklist` 前后对照——关标签只影响该标签的 shell 及其子孙（`ping -t` 一并消失）；仅终止宿主进程（不带 `/T`）后 shell 与孙进程同样消失，说明回收来自 Job 而非父进程级联。

**已知例外（如实登记，不掩盖）**：**Windows 打包应用（AppX/UWP，如 Win11 自带 Notepad）会脱离调用方 Job**——这是 AppX 激活的既有行为，不是本模块可控项。这类进程在宿主退出后可能残留，需按系统正常行为理解；普通 Win32 子进程（`ping`/`cargo`/`node` 等）仍在 Job 内。

**实操建议**：要收干净就用**关标签**（`user_terminal_close`）——它对整棵 Job 生效且不依赖宿主退出路径；杀宿主时 AppX 类型的孙进程可能留在外面，属上面已登记的例外。

**降级项（与 `docs/05` SH-071 同步）**：主窗口关闭当前语义是**隐藏到托盘**，不是退出进程，因此整树回收发生时机是「应用真正退出 / 进程崩溃 / 用户关闭标签」，而非「关窗口」。托盘退出路径必须走到 Tauri 托管状态的析构，才触发 `close_all`。

**服务商文档的写入规则**（`save_providers`）：整份文档一次写入并带 `expected_revision` 乐观锁，不拆逐条 op——半途失败留下"改坏一半的服务商列表"比整份不写更难恢复。校验拦下四种情况并报错而不是静默修：id 为空、id 重复、active 指不到任何 id、`models` 行缺 id 或重复。`secret_ref` 额外要求**改写前即合法**：DPAPI 的文件名清洗是剔除字符而不是报错，若允许 `..\evil` 这类名字被静默清洗，设置页会按原名报告"已配 Key"而后端按清洗后的文件读，第一次运行就变成"配了却说没配"。由 id 派生的名字在派生阶段已经把分隔符换成下划线，因此天然是安全文件名，这种情况放行。

**模型清单与生效档的一致性**：`models` 非空且 `model` 非空时，`model` 必须是 `models` 里的一行（`save_providers` 与 `save_settings` 两个写入口都校验）。理由是可见的：席位下拉只列 `models`，生效档不在清单里就意味着"跑着一个选不出来的模型"，用户随手点一下别的行就把档位换掉而不自知。`save_settings` 改生效模型时也要拦——它走 `update_config`，不经过 `save_providers` 的校验，漏一步就能写出这种文档。

**字段名的大小写**：命令返回值用 camelCase（`baseUrl` / `secretRef` / `contextWindow`），`config.toml` 落盘用 snake_case（`base_url` / `secret_ref` / `context_window`），`ProviderProfile` / `ModelProfile` 用 `#[serde(alias)]` 让 JSON 侧两种写法都接受。alias 不是风格照顾：serde 对结构体字段**不做**命名转换，认不到的键会被容器级 `#[serde(default)]` 静默填成缺省值，前端送 `baseUrl` 而字段只认 `base_url` 的话，写进去的就是一个空端点而不是报错。

### 4.1 模型能力声明与实测探针（SH-132）

**为什么"声明"不够**：两个活证据，都坏得没有声音。

1. `web_search_preview`：端点接受了这个参数、HTTP 200、响应结构正常，但**静默忽略**——响应里没有搜索痕迹，模型也没表现出用了它。没有任何一层报错，只有"以为开了"。
2. Sensenova 的推理档位反向（2026-11-09 实测，同一问题）：`reasoning_effort=high` 的 `reasoning_content` 只有 7 字符，`low` 是 254 字符。高档反而更少，说明端点根本没识别这个字段——这与"该模型不区分档位"是两回事。

因此能力拆成**两栏**：**声明值**（谁说它行）+ **实测结论**（测过没有）。两栏互不覆盖：探针只写 `verified`，绝不改声明值，否则"填错了"会被一次探测洗成"对的"。

**四层来源（高 → 低）**

| 层 | 来源 | 写入口 | 徽标 | 说明 |
| --- | --- | --- | --- | --- |
| 1 | 手动 | 设置页改 `context_window` / `max_tokens` / `input` / `reasoning_efforts` → `save_providers` | 手动 | 探针不覆盖；改回自动来源只能手改文档 |
| 2 | 端点元数据 | `GET /models`（`/models/{id}`） | 端点 | 只认字段名与类型都对得上的值 |
| 3 | 内置表（精确） | `resources/model-catalog.json`，`host + id` 精确命中 | 内置表 · `data_updated_at` | 随二进制发布，`include_str!` |
| 4 | 推测（家族） | 同表 `families[]` 正则命中 | 推测 · `data_updated_at` | 只写"所有已知成员都成立"的公共下限 |
| — | 未知 | 以上都没有 | 未知 | 不猜：交给探针或用户 |

- **匹配必须带 host**：实测 `deepseek-flash` 在 `api.deepseek.com` 是 text+image / 393216 输出，在 `token.sensenova.cn` 只有 text / 65536。只按模型名匹配会把一家的能力安到另一家头上。
- **家族规则全串匹配**：即使规则漏写 `$`，`^deepseek-chat` 也不能前缀吃掉 `deepseek-chat-v2` / `-preview` / 日期后缀的专属条目；精确条目永远优先。
- **端点声明 ∩ 声明档位**：`reasoning`（能力项 id）的可选档 = 声明（本行 `reasoning_efforts` 的键，或内置表的 `reasoning_levels`）∩ 端点 `effort.supported_levels`（端点给了这份清单时）。端点明说没这档，界面不给、请求不发。
- 内置表只收实测过的端点；主流但未实测的**不收录**，宁缺勿编。

**能力项 id（唯一登记表 `capability::ITEMS`）**：`vision`（布尔）/ `tools`（布尔）/ `builtin_web_search`（布尔）/ `reasoning`（档位）/ `context_window`（数值）/ `max_output`（数值）。新增能力只改这张表；未登记的项不丢弃，原样透传到视图的 `other`。

**五态（实测结论）**

| `state` | 含义 | 界面文案 |
| --- | --- | --- |
| `verified` | 实测通过（声明为真且确实生效） | 已验证 |
| `mismatch` | 实测与声明不符（含"声明有、实测无"与反向） | 与声明不符 |
| `unverified` | 没测过 / 没测成（瞬时失败） | 未验证 |
| `probing` | 探测进行中（后台已登记、尚未有结论） | 检测中 |
| `unjudgeable` | 数据采完了，但判据给不出结论（比值不足 / 触顶） | 不可判 |

`probing` 只给**有探针的能力项**（`vision` / `tools` / `reasoning`）：上下文窗口、输出上限、托管搜索本来就不探，它们必须显示 `unverified`，不许用「检测中」冒充"正在测"。

`unjudgeable` 与 `unverified` 必须分开：前者是"测过了，只是这个问题在这个端点上没有答案"，后者是"没测成"。混成一个词，用户会把「不可判」读成"探针坏了"或"能力不可用"。设置页对 `unjudgeable` 显示说明文案（「该端点无法判定推理档差异，不影响使用」）并提供手动重探入口。

**`429` / 限流的语义是「未验证」，绝不是「不生效」**：这两个结论后果完全不同——前者是"不知道，稍后重试"，后者会让用户去关掉一个其实好用的能力。错误文案必须写明是限流。

**探针判据（阈值都在这里定，代码里不许留魔法数）**

- **视觉**：`256×256` 纯色 PNG（红 `#C81414` / 绿 `#148C28`，`max_tokens`/`max_output_tokens = 512`），两张图各问一次「这是什么颜色」，**两问都对**才算生效（只对一张 = 蒙对的概率太高）；正文为空时回读 `reasoning_content`（部分推理模型把答案全放那儿），仍为空 → 未验证。任一问错或答"看不到图" → 与声明不符。尺寸不能用小图：实测 LongCat 对 `64×64` 会误答 gray，太小会制造"不支持视觉"的假阴性。
- **推理**：题面固定为**短算式 + 自检**（「请先计算，再自检一遍，只输出最终数字：`((17×23−19×19)×4+7!÷5!)`」，答案 162），`max_tokens = 512`；取声明档位的**最低档与最高档各采样 3 次**（交错发：低→高→低→高→低→高，避免预热漂移被记到高档头上），相邻请求间隔 `≥ 1100 ms`。指标取 `reasoning_tokens`，缺失时退化为正文长度，再退化为输出 token 数；中位数比较。
  - 噪声带 = `max(15% × 两档较大中位数, 2 × 档内极差)`。15% 是**跨轮漂移**下界（同一端点同一配置实测中位数在 low 69–99 / max 110–161 间漂移）；离散度用**极差**而非 MAD——n=3 时 MAD 会被一次幸运的紧采样压到 0/1，2026-11-09 round 1 的高档 `[104,124,125]`（MAD=1）就因此被判成「生效」。常数 `REASONING_NOISE_RATIO` / `NOISE_DISPERSION_K` 写在 `capability.rs` 并注明来源。
  - **效应/噪声比** = `|高档中位数 − 低档中位数| / 噪声带`，报告值必须带它，不只给结论。
  - **比值 ≥ 3 且零触顶**才允许下确定结论：方向为正 → **生效**；方向为负 → **字段未被识别**（文案「端点未识别该参数（高档反而更少）」）。
  - **比值 < 3，或任一档任一触顶 → 数据不足 → 最终落「不可判」**。`< 3` 时"生效"与"没用"都不许说——说"它没用"和说"它有用"一样需要证据。门槛取 3 而不是 2 的理由是**不对称**：声称"这个功能可用"需要的证据，比声称"我不知道"多。2026-11-09 概率题一轮比值 10.28 判生效、另一轮 0.79 判不足；把 10.28 那轮固化，运气好的一次就被写成永久事实，而且它不会自己暴露——反复翻案至少下一次会打脸，侥幸固化不会。
  - **触顶守卫**：样本 `completion_tokens >= max_tokens` 即标 `censored`（低档同样算——低档贴顶说明题目对它也过难，效应量会失真）。`censored` 计数进缓存与证据文案，不是内部状态。**不许用截断数据算出生效**：截断会把"预算不够"伪装成"想得少"。
  - **每档样本少于 3 个 / 档内 `MAD / 中位数 > 50%` / 噪声带被离散度撑起** → 同样「数据不足，无法判定」。
  - 「我不知道」必须是合法结论：只有"生效/不生效"两个出口时，任何不稳定数据都得被强行归到一边，于是必然翻案（2026-11-09 单样本实测同一端点出现 56→191 判生效、98→66 判未识别两次相反结论）。
  - **「生效」「字段未被识别」「不可判」必须彼此分开**：合并会把"端点不认这个字段"误判成"模型行为差异"，排查方向直接跑偏；把"判不出"说成"没效果"，会让用户去关掉一个其实好用的能力。
- **工具调用**：给一个必然需要调工具的请求，看响应里有没有 `tool_calls`；端点显式声明 `tools=false` 时直接判不符，不发请求。
- 探针**只写** `verified` / `verified_levels` / `samples` / `censored` / `unjudgeable` / `checked_at_ms` / `elapsed_ms` / `evidence`，不写 `source`、不改声明值。`elapsed_ms` 是本项探针的实际耗时；`None` 表示没测到（历史缓存 / 请求失败 / 图片编码失败），**不是 0 ms**——取证时要按项贴耗时，混进 0 会被读成「没打请求」。`samples` 是推理档每档的原始指标值（`{"low":[…], "high":[…]}`），`censored` 是每档触顶样本数：**不存结论了事**，翻案时要能一眼分出是数据抖了、被截断了，还是判据写错了。

**缓存与失效**：缓存键 = `base_url` + 协议族 + `model` + **密钥指纹**（sha256 前 8 字节 hex，不含明文）+ **探针版本**（`PROBE_VERSION`：题面 + 判据 + 每档采样次数 + 输出上限一起算出的常量）。换端点 / 换协议 / 换模型 / 换 key / **改探针**任一项即落到另一条记录；缓存文件自带版本号，版本变更整表作废（宁可重探，也不拿旧语义的记录当真）。探针版本进键的原因：改了题面或判据却不作废旧结论，等于拿旧尺子量新东西，改进本身没法被验证。首次使用某模型时后台补探，不阻塞回合。

**「不可判」是终态，不是粘性缓存**：判据给不出结论时写 `unjudgeable = true` 并缓存，之后**不再自动重探**（只有换 key / 端点 / 模型 / 探针版本才自然失效）；设置页可手动重探一次（`probe_capabilities(force=true)` 先作废该条缓存再重探）。这与粘性缓存的区别：粘性缓存把"不确定"藏成"数据不足"还反复重跑，用户看到的是会变来变去的结论；「不可判」是一次写定、语义明确的答案——"该端点无法判定推理档差异，不影响使用"。瞬时失败（网络断 / 429 / 超时 / 预算用尽）**不属于终态**：不写 `unjudgeable`，下一次探测还会重试。

**调度与超时**：探针**只在后台任务里跑**，任何用户交互路径都不 `await` 它——回合启动时 `spawn`，设置页「重新探测」也只登记后立刻返回。同一缓存键并发去重（`Inflight`），重复点击 / 重复启动不会打两轮请求。

- 单模型总超时 **30s**；其中**推理段单独 20s 预算**——超预算记「数据不足」，已采样本照样留档，不让推理段把视觉/工具的结论一起吞掉。预算用尽属瞬时失手，不是终态，下一轮会重试。
- 视图态 `probing`（「检测中」）：与 `unverified`（测过没测成）、`unjudgeable`（测完判不出）、`mismatch`（不符）语义不同，不能合并。设置页在还有 `probing` 项时自行轮询到结论，并显示已耗时计数 + 「预计 10–20 秒」——静态文字会让人以为卡死。
- 失败（网络断 / 429 / 超时）**只影响 `verified`，不影响模型可用性**：不写声明、不改 `input`、不禁用模型。

**成本量级**（写进设置页可见文案）：每模型首次检测 **9 次最小请求**——视觉 2 次（各含一张 256×256 图）、工具 1 次、推理 6 次（low / max 各 3 次，交错采样，上限 512 token），约 **10–20 秒**（deepseek-flash 实测：视觉 ~3.5s + 工具 ~0.7s + 推理 12–15s）。prompt 侧每问几十 token；推理 token 由模型决定（deepseek-flash 实测每次 79–201 completion token，两档合计约 630–800）。结果按缓存键只测一次。

**标定数据（2026-11-09，`deepseek-flash`，`api.deepseek.com`；同一端点上的实测，四条件互斥的证据）**

| 题面 | 上限 | low 样本 | max 样本 | 效应 | 效应/噪声 | 触顶 | 单轮耗时 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 长链题 + 写步骤 | 4096 | 507 / 502 / 1022 | 2257 / 3610 / 4096 | 7.1× | 2.13 | 2/3 | 106s |
| 同题 | 1024 | 132 / 222 / 204 | 787 / 422 / 1024 | 3.86× | 0.82 | 3/3 | ~37s |
| 分步推导（每步 ≤10 字） | 1024 | 245–1024 | 757–1024 | 1.1–3.4× | — | 2–3/3 | — |
| 注水题（只要数字） | 1024 | — | — | 1.24× | 0.74 | 0 | — |
| 短算式 + 自检（现行） | 512 | 86–99 | 98–201（中位 110–161） | 1.1–1.6× | 0.2–0.4 | 0 | ~18s |

短算式题先后跑过两组，正是这次判据改版的证据：

1. 第一版判据（5% + 3×MAD，门槛 3）：5 轮为 **E / I / I / I / I**。round 1 的高档三样本 `[104,124,125]` 恰好很紧，MAD 只有 1，噪声带塌到 6.2，40 的差被算成效应/噪声 6.5 → 判「生效」。这不是端点变好了，是一次幸运采样。
2. 现行判据（15% + 2×极差，门槛 3）：同一端点 5 轮全 **I（不可判）**，样本为 low `[86,94,95]/[90,86,93]/[96,92,99]/[138,99,79]/[86,99,90]`、max `[100,135,122]/[139,166,106]/[98,130,110]/[201,161,121]/[103,147,112]`，效应/噪声 0.2–0.4，零触顶。结论一致，且如实反映"这个端点的推理档差异小于它自身的抖动"。

**注意旧 `max_tokens=512` 本身就在污染数据**：长链题下 low 实测 507 / 502 / 1022，已贴到甚至超过上限；此前那些翻转有相当一部分不是参数噪声，是截断造成的。所以测量用的预算必须留足余量——**截断会伪造结论**。

结论：效应量与"要求写推导"强耦合，要求越多越容易触顶；**大效应、零触顶、耗时短、成本低四个条件在这个端点上互斥**。因此不再追求"调出大效应"，而是短题小效应 + 高门槛：判得出就报，判不出如实说「不可判」。

**手动覆盖的判定**：设置页写面不带 `capabilities`（它只属于视图，不属于 `config.toml`）。`save_providers` 逐项比对旧记录：`context_window` / `max_tokens` / `input` / `reasoning_efforts` 有变化的项标 `source = "manual"` 并清空实测留档；没变的项沿用旧来源。

判定看**记录**而不是看"值从哪读出来"：只有显式 `source = "manual"` 的记录才不采纳探针结论。若某行的 `input` 里写了 `image` 而没有任何能力项记录，界面同样标「手动」（值确实来自用户配置），但**实测仍会校验它**——否则声明了视觉的模型永远测不出「与声明不符」，探针就成了摆设。两条语义合起来是：手动 = 声明值以用户为准；实测 = 只写 `verified`，从不改声明值。

**落盘形态（additive，不写 = 全部按未知）**

```toml
# 能力来源与实测留档（SH-132）：能力项 id → 来源 + 实测结论。
# 值本身**不在这里**（取本行的 input / context_window / max_tokens /
# reasoning_efforts / 内置表），这里只存"谁说它行、测过没有"——同一事实落两处
# 迟早各自漂移（SH-096 的档位串段事故就是这么来的）。
[providers.models.capabilities.vision]

```

键不做白名单：`audio` / `pdf` / `prompt_caching` / `native_web_search` 等扩展位现在只留结构位、不填值，未识别的能力项原样透传到设置页「其他」分组，新增能力不需要改配置结构。

**`get_settings` 的视图面**：每个模型行多一个 `capabilities`（能力项 id → `{value|levels, source, state, catalogUpdatedAt?, evidence?, checkedAtMs?}`）+ `other`（扩展项原样透传）；`thinkingLevels` / `defaultReasoningLevel` 是档位清单与默认档的**唯一真源**，前端不再自带一份。

```
 2. 环境声明          # 每轮重算：OS / Shell=cmd /C / 时间与时区 / 权限档 / 隔离机制 / 网络 / Git
 3. 项目规则          # AGENTS.md 向上查找的注入结果（无规则时整段省略）
 4. 工作区与文件引用  # 工作区路径、@ 引用语义（沙箱语义归 2 的「权限档」，不重复写）
 5. 工具使用规范      # 工具选择优先级（apply_patch 优先于 shell 写入）、并行调用规则
 6. 沙箱与网络        # 默认断、会话级放行、断网必失败清单
 7. 验证纪律          # 可本地验证 / 需真机目视 / 无法验证 三分类
 8. 审批与安全        # 会触发审批的操作、被拒绝后如何调整策略、密钥不读取不输出
 9. 不可信工具输出    # A-R6：MCP 返回值是数据不是指令
10. 技能              # 仅当技能目录非空时注入
11. 计划模式          # 仅当处于计划态时注入
12. 回答风格          # 面向终端的简洁汇报格式；「不编造未验证结果」只在验证纪律里说一次
```

**去重规则**：同一个事实只在一个块里说。网络状态只在环境声明里报（与状态条同措辞），怎么申请授权只在「沙箱与网络」里说；沙箱模式语义只在「权限档」里说；「未验证不得声称为已通过」只在「验证纪律」里说。

**环境声明细则**（`prompt.rs::environment_block`）：

- `Shell：cmd /C` 是**常量声明**。命令经 `cmd.exe` 执行，不做 PowerShell 版本探测——探测一个并不存在的执行器只会产生错的前提。
- `权限档` 与 `隔离机制` **分两行**：前者是策略（只读 / 工作区写入 / 完全访问），后者是机制（AppContainer / 逻辑沙箱），两者独立变化，合并会掩盖「策略是工作区写入但没有 OS 隔离」这种关键组合。
- `网络` 行取**真实授权状态**（`sandbox::network::global().is_granted(session)`），且与隔离机制联动：`logical` 下恒为「未生效（无 OS 隔离）」，无论是否授权，**不得**写成「已断网」或「已放行」。
- 时间、Git 这类探测项失败时**整行省略**，不得填占位符或猜测值。

**项目规则细则**（`rules.rs::discover`）：

- 从工作区根逐级向上查找 `AGENTS.md`，直到盘符根；外层在前、内层在后，**同名二级标题以内层为准**（内层覆盖外层），外层独有小节保留。
- 按二级标题切分后**按标题语义分层**，位置不参与判定（位置会随文档重排而变，语义不会）：
  - `Must`（标题含「铁律 / 原则 / 红线 / 安全 / 边界 / 保护」）：必须进上下文；超预算**按行截断**，不允许整节消失。
  - `Guard`（标题含「禁止 / 约定 / 约束 / 规范」）：优先于普通说明，装不下则整节丢弃。
  - `Other`：填满剩余预算即可。
- 注入正文 ≤ **1000 tokens**（估算：CJK 1 字符 = 1 token，ASCII 4 字节 = 1 token）。
- 未注入的小节标题记入 `dropped`、被截断的记入 `clipped`；两者都以**标题列表**形式进日志（**不允许只记数量**——计数看不出来被裁掉的是铁律还是附录）。`clipped` 每条还要带**截到第几行 / 共几行 / 首条未注入行**，否则"截断"仍然看不出后果。留痕装得进预算时同时写进注入正文尾部；装不下时正文只报数量、标题进日志。
- 若 `Must` 集合本身就超过 1000，实现按文档顺序截断靠后的 Must 小节，并在交付说明里报「必须保留 X / 建议裁剪 Y」，由用户决定如何处理，**不得**自行抬高预算；优先的解法是压缩 AGENTS.md 里重复的论述，而不是加预算。
- **硬保险**：`injected_rules_must_contain_iron_law_and_degradation_redline` 直接断言真实 `AGENTS.md` 的注入正文里逐字含有「0. 铁律」与「11.3 退化红线」，且这几节不得出现在 `dropped` 里。改分类器、改 `AGENTS.md`、调预算中的任何一种把红线弄丢，`cargo test` 立刻红。
- 指纹覆盖**未裁剪全文**，因此「预算裁掉了一半」与「原文变了」是两件可区分的事。

**不变量**：① 全文 ≤ 2500 tokens（其中项目规则 ≤ 1000）；② 条款为命令式短句，每条一行；③ 环境声明每轮动态注入（权限档 / 隔离机制 / 网络授权变化必须反映）；④ 禁止在系统提示中写示例对话（few-shot 放用户轮）；⑤ **内容锁**：`PROMPT_VERSION` + 全文 sha256 前 16 位每轮进日志，全文快照由 `src-tauri/tests/fixtures/system_prompt.v1.txt` 锁住，改提示词必须显式升版并更新快照。

### 6.2 工具描述规范

- `description` ≤ 200 字符，首句说"做什么"，次句说"何时用/不用"。
- 参数描述必须含约束（如 `timeout_ms` 的默认值与上限），禁止只写类型名。
- 高风险工具（execute/destructive）描述中显式声明会触发审批，降低模型被拒后的"意外感"。

### 6.3 错误回填格式（工具结果 → 模型）

```
<tool_result name="..." status="error|denied|cancelled">
  <error_code>PATH_OUTSIDE_WORKSPACE</error_code>
  <message>人类可读本机语言一句话</message>
  <suggestion>可执行的下一步建议（如：改用工作区内路径，或请求用户授权）</suggestion>
</tool_result>
```

**不变量**：① `error_code` 为枚举（见 `agent_loop/error_codes.rs`），禁止自由文本当 code；② `denied`（用户拒绝）与 `error`（执行失败）严格区分——被拒绝后模型应换策略而非重试；③ MCP 工具结果外层再包 `<untrusted_content>` 标记；④ 输出截断时标注 `truncated: true` 与原始大小。

### 6.4 Compaction 摘要格式

压缩总结必须保留的固定字段：`任务目标 / 已完成事项 / 关键文件与改动 / 未解决问题 / 下一步`。摘要写回 rollout 为 `Compacted` 项，resume 时据此重建。

### 6.5 评估基线挂钩

- 基线任务集与评分脚本位于 `evals/`（SH-028 建立 v0，SH-073 扩展至全集）。
- **判定的分母是「当日对照」，不是冻结基线**：每次评估当天先跑对照臂 `SHANIU_EVAL_ROLE=control SHANIU_EVAL_ABLATE_AR6=1`（≥5 次，`evals/control.json`），再跑实验臂（默认，`evals/latest.json`）。判定只在**同日、同端点、同模型、同参数（任务集/轮数上限/重复次数）**的两组之间做；任一不一致 `score.mjs` 直接拒绝下结论（exit 2）。
- **固定步骤（顺序不可换；跳过任何一步都得不到结论）**：
  1. 固定端点与模型（`SHANIU_TEST_BASE_URL` / `SHANIU_TEST_MODEL`），当天不再更换；
  2. 对照臂：`SHANIU_EVAL_REPEATS=5 SHANIU_EVAL_ROLE=control SHANIU_EVAL_ABLATE_AR6=1` → `evals/control.json`；
  3. 实验臂：`SHANIU_EVAL_REPEATS=5 SHANIU_EVAL_ROLE=treatment`（不设 `SHANIU_EVAL_ABLATE_AR6`）→ `evals/latest.json`；
  4. `node evals/score.mjs`。缺任一臂、跨日、端点半途更换、任务集或参数不一致 → **exit 2**，不得手改报告或换分母凑结论。
  只跑实验臂等于没有分母：`score.mjs` 在 `control.json` 缺失或样本 < 5 时直接拒绝；**禁止**用冻结基线临时充当对照。
- **冻结基线（`evals/baseline.<model>.json`）只作历史参考，不参与判定**。失效原因：实测端点漂移把整份基线整体上抬 32%/轮，跨日的冻结点已经不是同一把尺子，拿它当分母结论永远红且没有信息量。跨日对比无效是**已知事实**，不是待验证假设。
- 触发回归评估的变更：系统提示、工具描述、错误回填格式、compaction 逻辑、编排工具。
- 指标退化 >10% 阻断合并（AGENTS.md §5）。
- **判定样本必须是多次运行的中位数（≥5 次，`SHANIU_EVAL_REPEATS` 默认 5）**：单次运行不足以区分「能力退化」与「端点抖动」。两臂报告都保留每次运行的数字（含变红的那些）与中位数，禁止只留最好的一次。
- **成功率下降是硬否决**；`avg_turns` / `avg_total_tokens` 只在「中位数相对对照越阈 **且每次运行都越阈**」时才判红，否则记为观察项。
- 阈值不得为了「凑绿」而下调；要改只改「怎么得出结论」的方法（样本数、中位数、对照臂、一致性规则）。
- `SHANIU_EVAL_ABLATE_AR6=1` 是**评估消融开关**，只用于关掉系统提示里的「不可信工具输出」条款做对照；它不写进设置、不随会话持久化、默认不生效，输出包裹标记不受影响。
