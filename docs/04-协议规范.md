# SHANIU 协议规范

> 版本：v0.1｜日期：2026-11-05｜状态：活文档
> 本文档是前后端、工具系统、持久化的**唯一契约来源**。实现以此为准；schema 变更只允许 additive（新增 optional 字段/新增枚举变体），受健身函数 FF-104 与 `event_schema` 快照测试保护。
> 类型记法：Rust serde 语义。`?` = optional（`Option<T>` + `skip_serializing_if`）。

---

## 1. 事件协议（后端 → 前端）

### 1.1 信封

```rust
/// Tauri emit channel: "shaniu://event"
struct AgentEvent {
    event_id: String,        // ULID，单调递增，用于去重与断线对齐
    session_id: String,
    agent_id: String,        // "root" 或子代理 ULID
    parent_id: Option<String>, // root 为 null
    ts_ms: u64,
    msg: EventMsg,           // serde(tag = "type", content = "data")
}
```

> **状态（2026-11-05 核对）：本信封尚未实现，v2 待 M5**。当前 `TauriEventSink::emit` 直接序列化裸 `EventMsg` 发到 `shaniu://event`（`events.rs:84-90`），前端 `src/transport/types.ts` 也是裸 union——`event_id`/`session_id`/`agent_id`/`parent_id`/`ts_ms` 五个字段均不存在。信封由 02 文档 §2.6 ADR-104 为子代理泳道定义，落地任务为 SH-053（M5）。
> **后果**：§1.3 的协议不变量 ①（同 `turn_id` 内事件按 `event_id` 全序）与 ④（前端重连按 `event_id` 续播、缺口从 rollout 补齐）在 M5 之前**不成立**——没有 `event_id` 可用。M5 前前端**不得**据此设计去重/续播，事件顺序只能依赖单通道 FIFO。

#### 1.2.1 `tool_call_end.result`（预登记，待 SH-074 实现）

> 状态：**契约先行，尚未实现**。本节确定字段语义与兼容边界，代码由 SH-074 落地；在 SH-074 完成前，`result` 一律视为缺失。

| 项 | 规格 |
| --- | --- |
| 字段名 | `result` |
| 类型 | `Option<ToolCallResult>`；`ToolCallResult` = 枚举 `ok / error / cancelled / denied`（`serde(rename_all = "snake_case")`） |
| 序列化 | `#[serde(default, skip_serializing_if = "Option::is_none")]`——`None` 时**不产生该键**；缺失与显式 `null` 均视为"未提供" |
| 位置 | `EventMsg::ToolCallEnd { call_id, exit_code, error, result }`（`src-tauri/src/events.rs`） |
| 落地方 | SH-074 |

**语义**（唯一判据；落地后前端禁止再做文案匹配）：

| 值 | 含义 | 视觉口径 |
| --- | --- | --- |
| `ok` | 工具执行成功 | 中性 tone |
| `error` | 执行失败（含超时、非零退出、工具层错误） | danger tone（**仅此一态用 danger**） |
| `cancelled` | 用户/系统取消（`CancellationToken`） | 徽标 `text-tertiary`（"未发生"语义） |
| `denied` | 审批拒绝 | 复用现有 token `bg-line2 text-primary`（"用户主动决定"语义）。**不新增 `--color-warning`**——主题层变更归 SH-041 统一做，现在单加将来暗色主题还要补一份 |

**权威性：`result` 存在时是唯一状态判据**

| 规则 | 内容 |
| --- | --- |
| 状态判据 | `result` 存在时**唯一**决定节点状态；`exit_code` / `error` 退化为**证据字段**——仍保留在事件与节点上供排查，但**不参与状态判定** |
| 矛盾组合 | `result = ok` 但 `error` 非空 → 状态仍判 `ok`（以 `result` 为准），但 `error` 文案**必须照常渲染**；tone 按 `result` 决定（即中性色，不是 danger） |
| 责任归属 | 上述组合属**后端矛盾数据**：前端不得"修正"状态，只按 `result` 渲染并把矛盾记日志/上报，作为后端缺陷线索 |

**回退路径（`result` 缺失时）**——仅用于解析旧事件，**不是**长期判据：

| 判据（按序） | 结论 |
| --- | --- |
| `exit_code == 0` 且 `error == null` | `ok` |
| `exit_code != 0` 或 `error != null` | `error` |
| 无退出码且无 `error` | **不由 `tool_call_end` 裁决**，交轮次级收敛：轮次 `reason == cancelled` → `cancelled`，否则 → `error` |

- **回退路径不产出 `denied`**：审批拒绝在 `result` 缺失时落 **`error` 状态 + 「已拒绝」文案**（`error` 字段里的 `用户拒绝` 作为证据字段照常显示）。这是 `result` 缺失时唯一正确的兜底，与 SH-074 之前的既有行为一致，不算回归。
- **绝不把 `denied` 归成 `cancelled`**：`cancelled` 的语义是"没执行完/被打断"，`denied` 是"根本没执行、用户主动否决"。归错会同时污染两个指标——审计上看不出审批拦截率，用户也分不清"我拒绝了"和"它被中断了"。
- **本映射仅在 `result` 缺失时成立**：`result` 存在时必须用 `denied`，不得再走这条兜底；也不得靠 `error` 文案匹配去"认出"拒绝（识别责任在 `result`）。
- 回退的意义仅在于"旧 rollout 事件仍能解析"：M3 完成历史事件迁移后即可移除本表。

**残留缺陷（本节的诚实结论——这正是 SH-074 要消除的东西）**：

| 缺陷 | 现状 | 后果 |
| --- | --- | --- |
| `denied` 无独立状态 | 审批拒绝在 `result` 缺失时落 `error` + 「已拒绝」文案（正确兜底），但节点状态仍是 `error` | 审计上拒绝率无法统计，用户看不出是自己拒的还是执行失败 |
| `denied` 会被抹成 `cancelled` | 若该轮随后被取消，轮次收敛规则（`reason == cancelled` 且 `exit_code == null`）会把已拒绝的节点一并翻成 `cancelled` | 已拒绝 → 已取消，语义反向 |
| 同轮先失败后取消 | 后端 `Err(e)` 分支同样不带退出码，轮次取消时已失败节点也被改写 | 徽标从"失败"变"已取消"，`error` 原文仍在节点上，信息不丢但判据错 |
| 依赖外部信号 | 轮次级收敛依赖 `turn_completed.reason == cancelled` | 事件乱序/补播缺 `turn_completed` 时分类整体失效 |

**因此**：`result` 缺失期间前端无法可靠区分四态——`denied` 与执行失败混同、`cancelled` 会吞掉同轮的失败与拒绝。**不要**用 `error` 文案匹配补这个洞（后端三处各发一个中文字面量，改一处措辞全链路静默失效），也不要设计"看起来能区分"的判据。

**实现约束：节点级判据隔离**（防回归的关键，与字段同批落地）

| 约束 | 内容 |
| --- | --- |
| 节点携带 | `ToolCallNode` 增加 `result?: ToolCallResult`（`src/nodes/types.ts`），由 `tool-call.ts` 在 `tool_call_end` 时写入 |
| 轮次收敛隔离 | `turn.ts` 的轮次收敛**只在 `node.result === undefined` 时执行**；节点一旦有 `result`，完全跳过收敛改写 |
| 理由 | `denied` 的 `exit_code` 同样是 `null`，"取消时把所有无退出码节点翻成 cancelled"的规则会把已拒绝的调用抹成已取消；靠给每个状态加例外会随枚举增长持续漏，只有"权威信息优先于猜测"能一次收口 |

**兼容性要求**：

1. 纯 additive：新增 optional 字段，旧消费端忽略未知键即可（`event_schema.rs` 的未知字段容忍用例已覆盖该性质），无主版本变更。
2. **滚动升级不炸**：旧前端（不认识 `result`）继续走上面的回退判据；新前端在 `result` 缺失时同样必须回退到同一判据，**不得**把缺失当 `error`，也不得引入文案匹配。
3. **FF-2（`src-tauri/tests/event_schema.rs`）与 FF-104（子代理事件包装，SH-053）快照需同步**：`all_variants()` 增加带 `result` 的 `ToolCallEnd`，并断言 `result: None` 时序列化结果不含 `result` 键。
4. **落地后收敛反推**：`turn.ts` 的 `reason == cancelled && exit_code == null` 判据按上表"节点级判据隔离"包 `result === undefined` 条件；`tool-call.ts` 改为直读 `result` 写节点状态，`error` 只作证据字段。顺带修掉 `tool-call.ts` 关于未知通道的注释与实现不一致（QA 观察 1）。
5. 注意与既有 optional 字段的差异：`cached_input_tokens`、`exit_code`、`error` 目前是裸 `Option`（`None` 序列化为 `null`），本字段按 §顶部记法使用 `skip_serializing_if`；消费端必须同时容忍"键缺失"与"值为 null"两种形态。
6. **mock 传输层必须同步**：`src/transport/mock.ts` 的 `tool_call_end` 必须发 `result`，否则 dev 模式永远走回退路径，字段等于没接线（FF-2 也测不到）。

## 2. 工具协议（ToolSpec）

统一签名（以实现为准）：`ToolSpec { name: String, description: String, parameters: serde_json::Value }`（`tool_router/spec.rs`）。**`risk` 不在 `ToolSpec` 内**——风险等级由 `permission/policy.rs::risk_of(tool_name)` 集中映射（未知工具名默认按 `destructive` 处理，fail-closed），见 `docs/01` ADR-003。`executor` 由各工具实现 `ToolExecutor` trait 提供，非 `ToolSpec` 字段。模型可见性按当前代理 depth/profile 过滤。

| name | risk | 关键参数 | 返回要点 | 可见性 | 风险 / 状态（2026-11-05） |
| --- | --- | --- | --- | --- | --- |
| `unified_exec` | execute | `{cmd, cwd?, timeout_ms?, stdin?}` | 流式 stdout/stderr + exit_code | 全部 | 已实现；`execute`；结果态由 `ToolCallEnd.result` 承载（SH-074） |
| `apply_patch` | write | `{patch}`（结构化 diff，禁止绝对路径越界） | `{applied[], rejected[]}`；dry-run 先行 | 全部 | 已实现；`write_in_workspace`；结果态同上 |
| `read_file` / `list_dir` / `search` | read | `{path/pattern, ...}` | 内容（超 64KB 截断+标注） | 全部 | 已实现；`read`；结果态同上 |
| `plan` | read | `{action: enter/exit, plan?}` | exit 必须用户确认后生效 | 全部 | 设计意图，已拆分为 `enter_plan_mode`/`exit_plan_mode`，ADR-004 表述待同步 |
| `enter_plan_mode` | read | `{}`（无参） | 进入只读计划态，免确认（ADR-003），重复进入幂等 | 全部 | 已实现（`tools/plan.rs`）；`read`；结果态同上 |
| `exit_plan_mode` | — | `{plan}`（必填，Markdown） | 提交计划请求评审；批准后写 `.shaniu/plan.md` 并恢复完整工具能力，拒绝则留在计划态 | 全部 | 已实现；**`plan_review`**（M2 Plan Mode 退出确认，必须经审批通道） |
| `request_user_input` | read | `{question, options?}` | 用户答复 | 全部 | 未实现，**待排期（暂无卡）** |
| `spawn_agent` | write | `{task, profile?, budget_tokens?, allowed_tools?}` | `{agent_id}` | 仅 depth=0 | 未实现，**待 M5**（SH-052） |
| `resume_agent` | write | `{agent_id, instruction?}` | `()` | 仅 depth=0 | 未实现，**待 M5**（SH-052） |
| `wait_agent` | read | `{agent_ids[], timeout_ms}` | `[ExitSummary]`（部分超时） | 仅 depth=0 | 未实现，**待 M5**（SH-052） |
| `send_agent_message` | write | `{agent_id, text}` | 应答摘要 | 仅 depth=0 | 未实现，**待 M5**（SH-052） |
| `terminal` | execute | `{action: open/write/read/close, session_id?, data?}` | PTY 输出流 | 全部 | 未实现，**待 M7**（SH-070） |
| `mcp__<server>__<tool>` | 按声明映射 | server 提供 schema | 输出按不可信内容包裹 | 按信任级 | 未实现，**待 M6**（SH-060/SH-061） |

> **风险等级是 5 个值，不是"四级"**：`read / write_in_workspace / execute / destructive` 之外还有 `plan_review`（M2 Plan Mode 退出确认，走审批通道但语义独立于 destructive）。ADR-003 的"四级风险"是审批策略口径，运行时枚举多这一项，勿混。
> **工具结果四态**（`ok / error / cancelled / denied`）**不在工具返回值里**，由 `ToolCallEnd.result` 承载（SH-074，见 §1.2.1）；工具返回仍只有成功/失败 + exit_code + 输出文本。

`ExitSummary = {status: done/failed/cancelled, summary: String /*≤4KB*/, artifacts: String[], token_usage: {input, output}}`

**工具不变量**：① 任何 write/execute/destructive 工具的执行路径必经 permission broker，无后门（FF：approval_contract）；② 工具输出进入模型上下文前统一截断与编码；③ MCP 输出外层包裹不可信标记。

## 6. 上下文工程（Context Engineering）

> 本章是 Agent 行为质量的核心契约。turn 循环的骨架在 01/02 文档，但 Agent 好不好用主要取决于本章内容。本章内容以代码形式落地于 `agent_loop/prompts/`，**任何变更必须附评估基线回归结果**（05 SH-028/073）。

### 6.1 系统提示结构（固定顺序）

```
1. 身份与目标        # SHANIU 编码代理，一句话使命
2. 环境声明          # OS=Windows、shell=cmd.exe（经 `cmd /C`）、工作区路径、沙箱模式
3. 行为准则          # 简短命令式条款：先读后改 / 小步提交 / 不确定就问 / 禁止臆造 API
4. 工具使用规范      # 工具选择优先级（apply_patch 优先于 shell 写入）、并行调用规则
5. 沙箱与审批说明    # 当前模式下哪些操作会触发审批，被拒绝后如何调整策略
6. 输出规范          # 面向终端的简洁汇报格式，禁止寒暄与重复用户输入
```

**不变量**：① 总长度 ≤ 2K tokens；② 条款为命令式短句，每条一行；③ 环境声明每轮动态注入（沙箱模式变化必须反映）；④ 禁止在系统提示中写示例对话（few-shot 放用户轮）。

> **shell 口径**：以 `unified_exec` 的实现为准——`cmd /C`（无引号转义歧义、行为可测）。迁移到 PowerShell 属于改变模型可用动作空间，必须待 SH-028 评估基线建立后以基线回归数据决策（AGENTS.md §5），不得凭偏好直接改。
> 落地位置：`src-tauri/src/agent_loop/prompt.rs::system_instruction`（当前覆盖身份、环境、工具规则、审批与安全、计划态、输出风格六段）。

### 6.2 工具描述规范

- `description` ≤ 200 字符，首句说"做什么"，次句说"何时用/不用"。
- 参数描述必须含约束（如 `timeout_ms` 的默认值与上限），禁止只写类型名。
- 高风险工具（execute/destructive）描述中显式声明会触发审批，降低模型被拒后的"意外感"。

### 6.3 错误回填格式（工具结果 → 模型）

```
<tool_result name="..." status="error|denied|cancelled">
  <error_code>PATH_OUTSIDE_WORKSPACE</error_code>
  <message>人类可读本机语言一句话</message>
  <suggestion>可执行的下一步建议（如：改用工作区内路径，或请求用户授权）</suggestion>
</tool_result>
```

**不变量**：① `error_code` 为枚举（见 `agent_loop/error_codes.rs`），禁止自由文本当 code；② `denied`（用户拒绝）与 `error`（执行失败）严格区分——被拒绝后模型应换策略而非重试；③ MCP 工具结果外层再包 `<untrusted_content>` 标记；④ 输出截断时标注 `truncated: true` 与原始大小。

### 6.4 Compaction 摘要格式

压缩总结必须保留的固定字段：`任务目标 / 已完成事项 / 关键文件与改动 / 未解决问题 / 下一步`。摘要写回 rollout 为 `Compacted` 项，resume 时据此重建。

### 6.5 评估基线挂钩

- 基线任务集与评分脚本位于 `evals/`（SH-028 建立 v0，SH-073 扩展至全集）。
- 触发回归评估的变更：系统提示、工具描述、错误回填格式、compaction 逻辑、编排工具。
- 指标退化 >10% 阻断合并（AGENTS.md §5）。
