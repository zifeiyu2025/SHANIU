# SHANIU 协议规范

> 版本：v0.1｜日期：2026-11-05｜状态：活文档
> 本文档是前后端、工具系统、持久化的**唯一契约来源**。实现以此为准；schema 变更只允许 additive（新增 optional 字段/新增枚举变体），受健身函数 FF-104 与 `event_schema` 快照测试保护。
> 类型记法：Rust serde 语义。`?` = optional（`Option<T>` + `skip_serializing_if`）。

---

## 1. 事件协议（后端 → 前端）

### 1.1 信封

> 2026-11-06 定案：保留既有 `EventMsg` 载荷和命令签名，补齐会话信封；此前表内未实现的另一套字段名不作为适配层输入。TS 镜像位于 `src/transport/types.ts`，仅由 transport 消费，不修改 DSH 协议类型。

```rust
struct AgentEvent {
    event_id: String,          // 单调 ULID
    session_id: String,
    agent_id: String,          // 根代理为 "root"；子代理 ULID 待 M5
    parent_id: Option<String>, // root 明确序列化为 null
    ts_ms: u64,                // Unix 毫秒
    msg: EventMsg,             // 内部标签 serde(tag = "type", rename_all = "snake_case")
}
```

传输过渡期为 Tauri emit `shaniu://event`，载荷是上述信封；SH-094 切换 loopback WebSocket 时保持载荷不变。`msg` 内字段与 `type` 同层，**没有 `data` 子对象**。新信封类型不改变已有 EventMsg 变体与字段；广播由裸 EventMsg 切换为信封，接入方必须读取 `event.msg`，不保留双载荷通道。

当前根会话的 `session_id` 等于 `send_task` 返回的档案 ID（旧命令参数仍叫 `agent_id`），`agent_id` 固定为 `root`。新建及续写均绑定各自会话 ID；`event_id` 在同一进程内由共享单调生成器产生，编号与发送处于同一临界区，跨会话/续写不重置。`ts_ms` 是采集时钟，不代替 `event_id` 排序。**当前未持久化事件信封，也未实现断线续播**，不能据此承诺跨重启的游标连续性（SH-094）。

### 1.2 EventMsg 枚举

| type | 与 type 同层的字段 | 语义 / 当前生产状态 |
| --- | --- | --- |
| `turn_started` | `{turn: u32}` | 一次模型采样迭代开始；同一用户任务内可多次产生，下一次用户任务从 1 重新计数 |
| `turn_completed` | `{turn: u32, reason: TurnEndReason}` | 整个用户任务结束，turn 为最后一次采样序号；不是每次 turn_started 都有一个对应结束事件 |
| `agent_message_delta` | `{delta: string}` | 助手正文增量 |
| `reasoning_delta` | `{delta: string}` | 思考增量，独立于正文 |
| `tool_call_begin` | `{call_id: string, tool: string, args: JSON}` | 工具调用开始；不含 risk，风险从审批请求取得 |
| `tool_call_output_delta` | `{call_id: string, channel: IoChannel, delta: string}` | stdout / stderr 增量；当前只由 unified_exec 产生 |
| `tool_call_end` | `{call_id: string, exit_code: i32|null, error: string|null, result?: ToolCallResult|null}` | 工具终态；result 非空时为唯一状态判据 |
| `exec_approval_request` | `{request_id: string, tool: string, args: JSON, risk: RiskLevel}` | 后端审批请求；裁决或取消前工具挂起 |
| `exec_approval_resolved` | `{request_id: string, decision: ApprovalDecision}` | 类型已定义，**生产端未发送**，待 SH-025 接线补齐 |
| `plan_delta` | `{delta: string}` | 类型已定义，**生产端未发送** |
| `turn_diff` | `{files: string[]}` | 类型已定义，**生产端未发送**；不含补丁正文或 hunk 计数，SH-017 不得伪造 diff |
| `token_usage` | `{turn: u32, input_tokens: u32, cached_input_tokens?: u32|null, output_tokens: u32}` | 当次采样用量，不是累计值；缓存用量 None 序列化为 null |
| `error` | `{message: string}` | 错误说明，任务是否终结以 turn_completed 为准 |

`TurnEndReason = completed | cancelled | failed | budget_exhausted`；`IoChannel = stdout | stderr`；`RiskLevel = read | write_in_workspace | execute | destructive | plan_review`；`ApprovalDecision = allow | deny | allow_always`；`ToolCallResult = ok | error | cancelled | denied`。

#### 1.2.1 工具终态与关联

`result` 缺失或 null 时，消费端才允许按 exit_code / error 回退；不得根据错误文案猜测 denied。`result` 存在时即使 exit_code / error 与之冲突也不覆盖状态，但错误证据仍须展示。新增字段保持 optional，旧输入缺失与显式 null 均可反序列化。

`call_id` 来自模型，可能跨采样/用户任务复用，不能作为整份会话的永久节点 ID。适配层必须结合会话及调用发生次序建立节点身份，事件去重以信封 event_id 为准。审批按后端签发的 request_id 回执，不由前端生成授权 ID。

二期预留（M5，尚未进入当前 EventMsg）：`subagent_spawned {child_id, task, profile, allowed_tools}`、`subagent_exited {child_id, summary: ExitSummary}`、`subagent_message {child_id, direction, preview}`；direction 为 `to_child/from_child`。

### 1.3 命令（前端 → 后端，Tauri invoke）

下表沿用 Rust 参数名；前端 invoke 对象键按 Tauri 默认规则用 camelCase（如 `agentId`、`requestId`）。返回的结构字段以各类型 serde 定义为准，不据此自动改名。

| command | Rust 参数 | 成功返回 | 说明 |
| --- | --- | --- | --- |
| `send_task` | `{task: string, agent_id?: string}` | 档案 ID 字符串 | 无 agent_id 新建，有则续写；未返回独立 turn_id，不支持附件 |
| `cancel_task` | `{}` | `()` | 取消唯一活动任务；尚无按会话多路执行或子树级联 |
| `approve` | `{request_id: string, decision: string}` | `()` | 合法 decision 为 allow / deny / allow_always；broker 只处理 pending ID |
| `list_sessions` | `{}` | `SessionSummary[]` | 扫描 rollout 摘要，按更新时间排序 |
| `load_session` | `{agent_id: string}` | `SessionEntry[]` | 一次性历史投影，目前无分页游标 |
| `resume_session` | `{agent_id: string, task: string}` | `()` | 恢复后追加任务 |
| `fork_session` | `{agent_id: string, keep_items: usize}` | 新档案 ID 字符串 | 截断到调用/结果配对的安全边界；不是 event_id 游标 |
| `get_settings` | `{}` | 设置视图 | 非敏感字段 + hasApiKey，不返回明文密钥 |
| `save_settings` | `{base_url, model, workspace_root, api_key?, sandbox_mode?, approval_mode?}` | `()` | 配置落盘，密钥经 SecretStore 加密；可选安全档位缺省不变 |
| `store_api_key` / `has_api_key` | `{provider, key}` / `{provider}` | `()` / boolean | 只允许 config::SecretStore 访问密钥存储 |
| `dev_ping` | `{nonce}` | `()` | shaniu://pong 回显 nonce，不属于 AgentEvent 流 |
| `get_product_dirs` | `{}` | `{configRoot, dataRoot, workspaceRoot}` | 宿主解析的产品目录 |
| `pick_folder` / `open_in_explorer` | `{}` / `{path}` | string|null / `()` | 原生目录选择 / 打开既有目录 |
| `read_clipboard_text` / `write_clipboard_text` | `{}` / `{text}` | string / `()` | 宿主文本剪贴板 |

当前限制：`approve` 命令没有把 broker 的“未命中/已失效 ID”返回值传播为调用错误；非法 ID 不会触发执行，但成功应答不能当作审批已生效证据，SH-025 必须补齐拒绝回执与 resolved 事件。`steer_agent`、按会话 cancel、`get_config/set_config`、`set_mode` 尚未注册；Plan 进出当前走工具通道，退出仍需 broker 审批，不由适配层直接切换。

**接线验收不变量**：① 同一进程内事件按 event_id 全序并保留 session_id 归属；② tool_call_begin 必有配对 tool_call_end（含 cancelled/denied）；③ 审批挂起期间不得执行对应工具，取消允许撤单收口；④ 重连按 event_id 续播、缺口分页补齐是 SH-094 验收要求，当前信封和已有 rollout 历史投影尚不满足；⑤ SH-017 的 follow 首帧须提供 cursor / hasMore，不能用当前 load_session 全量返回冒充分页。

## 2. 工具协议（ToolSpec）

统一签名：`ToolSpec { name, description, json_schema, risk, executor }`。模型可见性按当前代理 depth/profile 过滤。

| name | risk | 关键参数 | 返回要点 | 可见性 |
| --- | --- | --- | --- | --- |
| `unified_exec` | execute | `{cmd, cwd?, timeout_ms?, stdin?}` | 流式 stdout/stderr + exit_code | 全部 |
| `apply_patch` | write | `{patch}`（结构化 diff，禁止绝对路径越界） | `{applied[], rejected[]}`；dry-run 先行 | 全部 |
| `read_file` / `list_dir` / `search` | read | `{path/pattern, ...}` | 内容（超 64KB 截断+标注） | 全部 |
| `plan` | read | `{action: enter/exit, plan?}` | exit 必须用户确认后生效 | 全部 |
| `request_user_input` | read | `{question, options?}` | 用户答复 | 全部 |
| `spawn_agent` | write | `{task, profile?, budget_tokens?, allowed_tools?}` | `{agent_id}` | 仅 depth=0 |
| `resume_agent` | write | `{agent_id, instruction?}` | `()` | 仅 depth=0 |
| `wait_agent` | read | `{agent_ids[], timeout_ms}` | `[ExitSummary]`（部分超时） | 仅 depth=0 |
| `send_agent_message` | write | `{agent_id, text}` | 应答摘要 | 仅 depth=0 |
| `terminal` | execute | `{action: open/write/read/close, session_id?, data?}` | PTY 输出流 | 全部 |
| `mcp__<server>__<tool>` | 按声明映射 | server 提供 schema | 输出按不可信内容包裹 | 按信任级 |

`ExitSummary = {status: done/failed/cancelled, summary: String /*≤4KB*/, artifacts: String[], token_usage: {input, output}}`

**工具不变量**：① 任何 write/execute/destructive 工具的执行路径必经 permission broker，无后门（FF：approval_contract）；② 工具输出进入模型上下文前统一截断与编码；③ MCP 输出外层包裹不可信标记。

## 3. 持久化格式

### 3.1 rollout（`rollouts/<agent_id>.jsonl`，一行一个 RolloutItem）

| variant | 内容 | 说明 |
| --- | --- | --- |
| `SessionMeta` | `{session_id, agent_id, parent_id, created_at, config_snapshot}` | 文件首行，必须存在 |
| `ResponseItem` | 模型请求/响应/工具调用的完整记录 | 主体，顺序与 event_id 对齐 |
| `Compacted` | `{range, summary}` | 压缩锚点，resume 时替换区间 |
| `SubagentRef` | `{child_id, rollout_path}` | 父文件中的子代理引用 |

fork = 复制文件截断到指定 event_id + 新 SessionMeta；resume = 重放至尾部后继续追加。

### 3.2 会话索引（`sessions/<session_id>.json`）

`{session_id, title, created_at, updated_at, root_rollout, agents: [{agent_id, rollout_path, status}], token_usage_total}`

## 6. 上下文工程（Context Engineering）

> 本章是 Agent 行为质量的核心契约。turn 循环的骨架在 01/02 文档，但 Agent 好不好用主要取决于本章内容。本章内容以代码形式落地于 `agent_loop/prompts/`，**任何变更必须附评估基线回归结果**（05 SH-028/073）。

### 6.1 系统提示结构（固定顺序）

```
1. 身份与目标        # SHANIU 编码代理，一句话使命
2. 环境声明          # OS=Windows、shell=PowerShell、工作区路径、沙箱模式、当前时间
3. 行为准则          # 简短命令式条款：先读后改 / 小步提交 / 不确定就问 / 禁止臆造 API
4. 工具使用规范      # 工具选择优先级（apply_patch 优先于 shell 写入）、并行调用规则
5. 沙箱与审批说明    # 当前模式下哪些操作会触发审批，被拒绝后如何调整策略
6. 输出规范          # 面向终端的简洁汇报格式，禁止寒暄与重复用户输入
```

**不变量**：① 总长度 ≤ 2K tokens；② 条款为命令式短句，每条一行；③ 环境声明每轮动态注入（沙箱模式变化必须反映）；④ 禁止在系统提示中写示例对话（few-shot 放用户轮）。

### 6.2 工具描述规范

- `description` ≤ 200 字符，首句说"做什么"，次句说"何时用/不用"。
- 参数描述必须含约束（如 `timeout_ms` 的默认值与上限），禁止只写类型名。
- 高风险工具（execute/destructive）描述中显式声明会触发审批，降低模型被拒后的"意外感"。

### 6.3 错误回填格式（工具结果 → 模型）

```
<tool_result name="..." status="error|denied|cancelled">
  <error_code>PATH_OUTSIDE_WORKSPACE</error_code>
  <message>人类可读本机语言一句话</message>
  <suggestion>可执行的下一步建议（如：改用工作区内路径，或请求用户授权）</suggestion>
</tool_result>
```

**不变量**：① `error_code` 为枚举（见 `agent_loop/error_codes.rs`），禁止自由文本当 code；② `denied`（用户拒绝）与 `error`（执行失败）严格区分——被拒绝后模型应换策略而非重试；③ MCP 工具结果外层再包 `<untrusted_content>` 标记；④ 输出截断时标注 `truncated: true` 与原始大小。

### 6.4 Compaction 摘要格式

压缩总结必须保留的固定字段：`任务目标 / 已完成事项 / 关键文件与改动 / 未解决问题 / 下一步`。摘要写回 rollout 为 `Compacted` 项，resume 时据此重建。

### 6.5 评估基线挂钩

- 基线任务集与评分脚本位于 `evals/`（SH-028 建立 v0，SH-073 扩展至全集）。
- 触发回归评估的变更：系统提示、工具描述、错误回填格式、compaction 逻辑、编排工具。
- 指标退化 >10% 阻断合并（AGENTS.md §5）。

## 7. 版本与兼容

- 协议版本随文档：`v1`（01 文档 M0–M4）、`v2`（02 文档新增 3 个事件 + orchestrate 工具）。
- 前端启动时与后端握手 `protocol_version`；主版本不一致拒绝连接并提示升级。
- 任何 breaking 变更 = 新主版本 + 新文档章节，禁止原地修改既有 variant 字段语义。
