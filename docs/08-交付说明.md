## 2. 安装与首次启动

**共同前提**：Microsoft Edge WebView2 运行时。Windows 11 自带；Windows 10 若缺失需先装（Evergreen Bootstrapper）。

### 2.1 MSI

1. 双击 `SHANIU_0.1.0_x64_unsigned.msi`。
2. **未签名会触发两处提示**：
   - SmartScreen / 浏览器下载拦截：「Windows 已保护你的电脑」→ **更多信息 → 仍要运行**；
   - UAC 提权确认：发布者显示为「未知发布者」。
3. MSI 默认按机器安装到 `Program Files`，因此需要管理员；卸载走「应用和功能」。

### 2.2 便携 ZIP

1. 解压到任意用户可写目录（**不要解压到 `Program Files`**：便携模式会在同目录建 `data\`，需要写权限）。
2. 双击 `SHANIU.exe`；目录内 `portable.marker` 存在即启用便携模式。
3. 数据全部落在 `<解压目录>\data`，不写 `%APPDATA%` / `%LOCALAPPDATA%`；移动整个目录即可迁移。
4. 同样会触发 SmartScreen「未知发布者」提示。

### 2.3 数据根与本机隔离（验收/多实例时用）

解析优先级：`SHANIU_DATA_DIR` 环境变量 > `portable.marker`（`<exe>\data`）> 安装版（配置侧 `%APPDATA%\SHANIU`，数据侧 `%LOCALAPPDATA%\SHANIU`）。
设 `SHANIU_DATA_DIR` 时，配置侧与数据侧**同时**指向该目录——做回归、演示、多实例时必须这么做，不要往真实数据根里造会话。

## 3. 降级条款（12 张卡，原文见 `docs/05`）

以下条目在 `docs/05` 中都写在对应卡的完成注里，此处只做汇总与定位，不改写含义。

### 3.1 沙箱与网络（SH-021 / SH-022，`docs/05` 第 284 行）

- **a) `sandbox.os = "logical"` 档没有路径级写入边界、没有 OS 网络隔离**：MCP 子进程此时只有受限令牌 + Job，状态面显示 `not_isolated`；这是用户显式选择的降级档，不是默认档。另有逐 server 的 `unsandboxed = true` 显式豁免（必须填 `unsandboxed_reason`，否则配置校验直接报错）。
- **b) 网络授权是进程内内存态**：按会话记一次、子进程继承，**重启清零**；不引入 codex 式的全局落盘规则文件。
- **c) 状态条只显示会话短 id**（不解析标题，避免 root 作用域再猜当前会话）。
- **d) `shutdown()` 只在托盘退出路径调用**：进程被强杀时不走优雅回收，依赖下次启动的 `recover_pending` 按 `sandbox\acl\*.dacl` 备份还原 DACL。
- **e) 本轮未跑 `evals/` 基线回归**（改动只落在「原本零输出」的失败路径的说明文本上，评估成本与收益记在 SH-073 卡）。

2026-11-09 起这一条的降级面**已收窄**：MCP stdio 不再走逻辑沙箱，每个已信任 server 跑在自己的 AppContainer `shaniu.mcp.<id>` 里（证据见 §4.5）。

### 3.2 MCP 容器化（SH-064）

- 可用边界只有两条「合法回落」：全局 `sandbox.os = "logical"`，或逐 server `unsandboxed = true` + 原因。**单个 server 不会因为启动失败就静默退回受限令牌**——失败即 `blocked` 并给出缺失路径与下一步建议。
- 容器内只挂工作区档位的路径边界 + `allowed_roots`；`allow_network = false` 时不挂 `internetClient` 能力。

### 3.3 终端（SH-071，`docs/05` 第 797 行）

### 4.3 配置形态坑（已确认，供后来人）

`allowed_roots` 的元素是 **struct**，不是字符串：

```toml
[[mcp.servers]]
id = "e2e-echo"
command = "D:\\path\\to\\node.exe"
args = ["D:\\path\\to\\mcp-server.mjs"]
cwd = "D:\\path\\to\\workspace"
enabled = true
allow_network = false
allowed_roots = [{ path = "D:\\path\\to\\bin", access = "read" }]
workspace_access = "read"
```

写成 `allowed_roots = ["D:\\..."]` 会让整份 `config.toml` 解析失败 → 应用进入**配置只读**（fail-closed，原文件一个字节不动，`get_settings.configReadOnly` 回显原因），表现是「配置里的 server 不存在」。

### 4.4 风险档位默认值

MCP 工具没有 `annotations` 时默认风险档 = `destructive`，首次审查必须逐工具显式改写风险档，否则每次调用都会走审批。

## 5. 已知限制

### 5.1 本机 SKU 验不到的路径

- 「补 `NUL` 设备授权 → 撤销」在本机走 `AlreadyAccessible` 分支（`\\.\NUL` 的 DACL 已带应用包 SID），**本机跑不到**；该分支靠 CI runner（容器内 `cargo test`）覆盖。见 §3.6 SH-133。
- 设备 DACL 在**非管理员**下无权 `WRITE_DAC`：此时不改隔离语义，只上报 `NoPermission` 并 warn——容器内依赖 `nul` stdio 的命令会报 `Access denied`。

### 5.2 `logical` 档的能力边界

`sandbox.os = "logical"` 时：有受限令牌（特权剥离）+ Job 进程树回收，**没有**路径级写入边界、**没有** OS 网络隔离；状态条会以警示底色显示「未启用 OS 沙箱」。MCP 子进程在此档的状态为 `not_isolated`。

### 5.3 MCP 运行时安装位置

容器只能读取被授予 ACE 的目录。若解释器装在管理员目录（如 `D:\Programs\nodejs`、`C:\Program Files\...`）而当前用户无 `WRITE_DAC`，容器起不来 → server `blocked`。两个可用办法：把运行时（连同它依赖的解释器）复制到用户可写目录，再把配置里的 `command` 指到新位置（解释器所在目录由工具链授权自动覆盖，不需要写进 `allowed_roots`）；或逐 server 设 `unsandboxed = true` + 原因（显式豁免）。`blocked` 的界面文案直接写这两条，`WRITE_DAC` 只在括号里作为技术原因出现一次。

### 5.4 网络授权重启清零

网络放行按会话记在内存，进程重启即清零；子进程继承当次授权。没有全局规则文件——这是 v1 的有意设计。

### 5.5 其他

- 会话事件的条件化投递成立前提是**单窗口**；多窗口时走 fallback 的窗口会被饿死（`docs/04` §1.4）。
- 配置只读状态在 **MCP 连接器页**与**设置 → 通用页**各有一条横幅，两处挂同一个组件、同一条词典键（`get_settings.configReadOnly`，含出错行与文件路径）；横幅只在解析失败时出现。
- 未签名：无代码签名、无自动更新；SmartScreen 提示属预期。

### 5.6 首次连接 MCP 的等待成本（已知，默认路径已不再触发）

`8747aa2` 起，**默认路径不再有 1–2 分钟的等待**：默认工作区从用户主目录改为 `<data_root>\Workspace`（一个空的应用自有目录），真机连接 9.8 s（见 §1）。下面这段 105 s 的实测**保留**，因为它描述的是「工作区被配到很大的目录」时的机制，用户自己把 `[workspace].root` 指到大目录时仍会遇到。

**什么情况下会重新遇到**：用户显式把 `[workspace].root` 配成一个大目录（例如某个有几十万文件的资料盘目录）——这不是默认值的问题，是 ACL 递归传播本身的成本。此时的耗时仍按下面这张表线性增长，界面的等待说明（`1f1fd39` 起）继续保留。

一次失败运行的时间构成（隔离数据根、`D:\Programs\nodejs\node.exe`、工作区回落到用户主目录，`acl-audit.jsonl` + 日志时间戳）：

| 阶段 | 耗时 |
| --- | --- |
| 容器准备（发现陈旧 profile → 删除重建） | ≈ 0.1 s |
| `grant(C:\Users\jun, read)`（工作区根，成功） | **52.65 s** |
| `grant(D:\Programs\nodejs, read)`（失败，Win32 错误 5） | **2 ms** |
| `release` → `revoke(C:\Users\jun)` | **52.30 s** |
| 删除容器 profile | 4 ms |
| 合计（CDP 实测 invoke 往返） | **105.07 s** |

- **不是重试，也不是超时叠加**：这条路径没有任何重试；错误 5 的那一次只花 2 ms（同步返回）。慢的是**成功的那一次** ACL 写入与它对应的撤销。
- **根因**：`SetNamedSecurityInfoW` 写**可继承** ACE 时，系统同步把这颗 ACE 递归传播到整棵子树，耗时随文件数线性增长。同一个 API 的对照实测：空目录 74 ms、1 千文件 67 ms、1 万文件 653 ms（≈ 65 µs/文件）。工作区根为空时回落 `%USERPROFILE%`（`docs/04` §1.5.1），量级在数十万文件，于是单次约 52 s。
- **界面**：等待期间连接器在按钮下方常驻一行说明（在准备沙箱容器、为什么可能一两分钟），不再是「按钮点了没反应」。

#### 5.6.1 为什么把默认值改成应用自有目录

原来「什么都不配」= 把整个 `%USERPROFILE%` 只读授给容器。慢只是症状，真正的问题是**范围**：`C:\Users\<name>` 下有 `.ssh`、`AppData` 里的浏览器与编辑器登录态、以及整份个人资料，这些都不是 MCP server 需要的。默认值应该是最小可用范围，而不是「用户目录顺手能用」。

- 新默认：`<data_root>\Workspace`（便携版 `<exe>\data\Workspace`，安装版 `%LOCALAPPDATA%\SHANIU\Workspace`），与 `get_product_dirs` 交给界面的 `workspaceRoot` 同一口径，也由启动流程随数据根一起创建。
- `[workspace].root` 有值时仍以配置为准，默认值只影响「没配」的情况。

#### 5.6.2 过宽根被拒后怎么办

配置成下列形态作为**工作区根**（或 `cwd`、`allowed_roots`）时，授权直接被拒绝，错误原文同时落进 `acl-audit.jsonl`（`"action":"grant"`, `"result":"refused"`）并显示在状态面（server 变为 `blocked`，`reason` 里是完整原因）：

| 被拒形态 | 例子 |
| --- | --- |
| 用户主目录 | `C:\Users\jun`（尾斜杠、`..`、`\\?\`、junction 指向它同样被拒） |
| 盘符 / 共享根 | `C:\`、`D:\`、`\\server\share` |
| 系统目录 | `%SystemRoot%`、`%ProgramFiles%`、`%ProgramFiles(x86)%` |

- 判定用**规范化后的最终路径**比较（先 `canonicalize`，去掉 `\\?\`，再按 Windows 口径忽略大小写），不做字符串前缀匹配；**主目录的子目录照常放行**（`C:\Users\jun\work` 是合法工作区）。
- **`allowed_roots` 同样受限**：宽不宽看目录本身，不看它从哪个配置键写进来。`allowed_roots` 里放上述任一形态同样被拒、同样落审计，并复用同一套判定（`RootRole::UserPicked` 走同一个守卫），不是另抄一份逻辑——否则换个键就能绕过，而绕过它的往往正是被提示劝退后找别的路子的人。
- **怎么办**：把 `[workspace].root` 改成具体的项目目录；提示里给了形如 `C:\Users\jun\work` 的示例。没有「一键豁免」开关——需要更宽范围时，正确做法是显式把那个项目目录配成工作区，而不是把整个用户目录交出去。
- 工具链目录（`node.exe` 所在目录、`.cargo` 等）走另一条授权路径，**不受这条约束**：它们本来就可能落在 `C:\Program Files` 下，`node.exe` 在 `Program Files\nodejs` 是子目录；只有把 `Program Files` 本身当根才拒。

| 内容 | 位置 |
| --- | --- |
| 启动/运行日志 | `<data_root>\logs\shaniu.log.<YYYY-MM-DD>`（第一行写解析出的数据目录） |

| `NUL` 设备快照 | `<data_root>\sandbox\null-device.dacl` |

| 崩溃产物 | `<data_root>\crash\` |

- 数据根解析：`SHANIU_DATA_DIR` > `portable.marker` > 安装版默认。
- 「上次异常退出没还原」的判定：`sandbox\acl\` 下有 `.dacl` 残留，且日志里没有对应的还原成功记录。
