# FF-1 修复：RetryMode 归属改到 config（2026-11-16）

## 问题

D5 首版把 `RetryMode` 定义在 `model_client::retry`，并由 `config` 引用它，形成
`config → model_client`。CI run 43900774105 的 `gate` job 在
“依赖方向检查（FF-1，阈值 0）” 步骤报 2 条违规：

```
违规  src-tauri/src/config.rs:837  config → model_client（允许边表未包含该边）
违规  src-tauri/src/config.rs:870  config → model_client（允许边表未包含该边）
[check-deps] 失败：2 条违规（阈值 0）
```

docs/01 §2.3.1 明确 `config` 是共享基础设施、只依赖 `config`/`events`/`clock`，
不允许反向依赖业务模块。

## 修法

- `RetryMode` 移到 `src-tauri/src/config.rs`（配置项就是它的语义归属）。
- `model_client::retry` 改为 `use crate::config::RetryMode`，方向变成 E20
  （`model_client → config`，已有边）；`model_client` 的公开 re-export 保留，
  调用方路径不变。
- 不新增/修改允许边表：这是修方向，不是改架构规则。

## 第二个 CI 红灯（同一提交，紧随其后）

FF-1 修好重推（run 43902876294）后 gate 又红在 `tests/wire_field_consumers.rs`：

```
thread 'every_backend_wire_field_is_classified' panicked at tests\wire_field_consumers.rs:436:5:
后端 wire 结构新增了字段，但没有登记消费状态。
- EventMsg.ModelRetry 的字段 `unbounded` 未表态
```

原因：D5 新增了 `unbounded` 字段并让前端 adapter 读取，但漏登记
`tests/wire_field_consumers.rs` 的 RULES。已把它加入 `EventMsg/ModelRetry`
的 `fields`（前端 `adapter.ts` 读它决定 `mode: 'always'`，属 Read，不是 BackendOnly）。
本地当时只跑了 `--lib` 与 `event_schema`，没跑全量 `cargo test`，所以漏检——
后续改为推送前跑全量 `cargo test`。

## 验证

- `./scripts/check-deps.ps1`：`依赖方向检查通过（0 违规）`。
- `cargo test --lib retry_mode_defaults` / `always_mode`：1 + 3 全绿。
- `cargo clippy --all-targets -- -D warnings`：干净。
- `cargo test --test wire_field_consumers`：2 全绿。
- 全量 `cargo test`（所有目标）：全部 `test result: ok`，退出码 0；
  期间 `sandbox::tests::mcp_server_runs_inside_container_and_reads_workspace`
  在本机跑过红灯（容器内读工作区为空，环境相关），最终一轮为绿——如实记录，
  未改该用例断言。
