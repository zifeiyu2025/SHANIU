## 1. 项目概述

SHANIU 是一款 **Windows 桌面 Agent Harness 客户端**：在本地托管自主编码 Agent 的完整生命周期——任务输入、模型推理循环、工具执行、沙箱隔离、人工审批、流式渲染与会话持久化。

| 项 | 值 |
| --- | --- |
| 技术栈 | Tauri 2.12.5 + React 19.3.1 + Rust 1.99.1 + Vite 8.3.5 |
| 目标平台 | Windows 10/11 x64（首发，架构上保留跨平台沙箱扩展点） |
| 进程模型 | 单进程：Tauri Rust 后端承载全部 Agent 逻辑，WebView 前端通过 IPC 通信 |
| 开发方式 | 全部代码由 AI 编码代理产出，受 `AGENTS.md` 约束 |

### 1.1 目标（Goals）

- G1：提供完整的自主编码循环——用户下达任务后，Agent 自主规划、读写文件、执行命令、自我纠错，直到任务完成或被中断。
- G2：**真实沙箱**，不是"仅提示"——Windows 上通过受限令牌（Restricted Token）+ Job Object + ACL 实施文件系统/网络边界；策略无法满足时拒绝执行（fail-closed）。
- G3：风险分级审批——只读工具自由执行，写入/命令按沙箱策略与审批模式裁决，破坏性操作必须人工确认。
- G4：流式体验——模型输出、命令输出、diff 全部流式渲染，支持随时中断（CancellationToken）。
- G5：会话可恢复——rollout 持久化（JSONL），支持 fork/resume/replay。

### 1.2 非目标（Non-Goals）

- 不做多用户/协作/云端同步（单机单用户）。
- 不做自有模型推理，仅对接兼容 OpenAI Responses/Chat Completions 协议的远端或本地端点。
- 首版不做 MCP 市场/插件 UI 沙箱（保留协议扩展点，见 ADR-004）。
- 不打包子 Agent 并行编排（`multi_agents` 列入二期候选）。

### 2.2 有界上下文图（Bounded Context Map）

| Context | 职责 | 模型/语言 | 上游 | 下游 | 与邻接关系 | 翻译面 |
| --- | --- | --- | --- | --- | --- | --- |
| `ui`（前端） | 渲染会话流、审批交互、配置 | TypeScript/React | `events` | 用户 | conformist（完全消费后端事件模型） | `EventMsg`→视图节点（conversation-nodes 模式） |

| `tool_router` | ToolSpec 注册/路由/参数校验 | Rust | `agent_loop` | `tools/*` | shared kernel（ToolSpec 是共享契约） | JSON Schema ↔ Rust 参数类型 |
| `tools/*` | 具体工具执行（exec/patch/plan/fs） | Rust | `tool_router` | `permission`、`sandbox` | customer/supplier | 工具入参 → OS 调用 |
| `permission` | 审批模式、风险分级、裁决 | Rust | `tools/*` | `ui`（审批请求） | partnership | 工具风险等级 → 审批事件 |
| `sandbox` | 进程隔离原语（Windows） | Rust + Win32 | `tools/unified_exec` | OS | anti-corruption layer | 沙箱策略 → RestrictedToken/JobObject/ACE |
| `model_client` | LLM HTTP 流式客户端 | Rust | `agent_loop` | 远端 API | anti-corruption layer | Responses SSE → `ResponseItem` 流 |
| `rollout` | 会话持久化/fork/resume | Rust | `agent_loop` | 磁盘 | separate ways | `RolloutItem` ↔ JSONL |
| `events` | 事件协议定义+广播 | Rust | 全部 | `ui` | shared kernel | `EventMsg` → Tauri Event 序列化 |

### 2.3 依赖方向规则（不可违反）

`ui → events`；`agent_loop → {model_client, tool_router, rollout, events}`；`tool_router → tools/*`；`tools/* → {permission, sandbox}`；**禁止反向依赖，禁止 `tools/*` 直接访问 `model_client` 或 `ui`**。

## 3. 核心设计决策（ADR）

### ADR-001：Agent 主循环形态

| 驱动 | 优先级 | 依据 | 取舍 |
| --- | --- | --- | --- |
| 自主纠错需要"执行→观察→再推理"闭环 | 高 | codex `run_turn`（core/src/session/turn.rs） | 循环内嵌套流式处理增加复杂度 |
| 随时可中断 | 高 | ZCode `enqueueCancellableRuntimeCommand` | 取消传播需贯穿所有工具 |
| 上下文有限 | 高 | codex compact 模块 | 压缩可能丢失细节，需 rollout 兜底 |

**决策**：单线程逻辑循环（tokio task），每轮 = 请求模型（流式）→ 收集 tool calls → 经 permission 裁决 → 执行（支持并行只读工具）→ 结果回填 → 再请求。循环携带 `CancellationToken`；每轮采样前检查 token 预算触发 compaction。
**备选**：① 状态机驱动（ZCode TurnMachine）——表达力强但 AI 编程实现成本高，**拒绝**；② 无循环的一次性 chain——不满足自主纠错，**拒绝**。
**可逆性**：双向门。重构触发器：需要子 Agent 并行编排时升级为显式状态机。
**状态**：已决定。

### ADR-002：Windows 沙箱实现

| 驱动 | 优先级 | 依据 | 取舍 |
| --- | --- | --- | --- |
| AI 代理执行任意命令，必须真实隔离 | 高 | codex sandboxing/src/windows.rs | 实现复杂度高 |
| 全 AI 编程，需要可分阶段交付 | 高 | 一次性实现完整 ACL 引擎风险大 | 分 tier 渐进 |

**决策**：三级沙箱策略（沿用 codex 语义）——
1. `read-only`：可列目录/读文件，禁止一切写入与命令执行（不经子进程，纯策略裁决）；
2. `workspace-write`：命令经**受限令牌 + Job Object** 启动子进程，对工作区外路径写访问用 deny-ACE 封锁，网络默认禁用；
3. `danger-full-access`：直接执行，UI 全程显著标识。
**Fail-closed**：策略组合无法实现时报错拒绝，不降级为"提示后执行"。
**分阶段**：M1 先交付策略裁决层（逻辑边界）+ `read-only`/`danger-full-access`；M2 交付 RestrictedToken+JobObject；M3 补 deny-ACE 精细路径控制。
**备选**：① 仅提示无隔离——安全不达标，**拒绝**；② Windows Sandbox（MXC/容器）——重、依赖 Pro 版系统组件，**拒绝（首版）**，留扩展点。
**可逆性**：`sandbox` 是 ACL 防腐层，内部实现可替换。
**状态**：已决定（分阶段）。

### ADR-003：审批与权限模型

**决策**：Permission Broker 集中裁决（参考 ZCode permissionGate）。工具按风险分四级：`read`（自动放行）/ `write-in-workspace`（按沙箱模式自动或询问）/ `execute`（询问，可"本会话记住选择"）/ `destructive`（每次必问：git push --force、rm 递归、工作区外写入、网络上传）。
**Plan Mode**：`EnterPlanMode` 免确认进入只读计划态；`ExitPlanMode` 必须用户确认（复用审批通道，用户可附修改意见）——语义照抄 ZCode 的 plan-mode-approval-boundary。
**审批 UI 不可伪造**：审批请求由 Rust 后端发出、经 Tauri 原生窗口事件通道，前端渲染仅展示；裁决结果只接受后端校验过的审批 ID 回执。
**状态**：已决定。

### ADR-004：工具系统与扩展

**决策**：统一 `ToolSpec`（JSON Schema）+ `ToolExecutor` trait + `ToolRouter`（照 codex 模式）。内置工具首批：`unified_exec`（命令执行，流式 stdout/stderr、超时、stdin、取消）、`apply_patch`（结构化补丁，禁止任意写文件绕过审批）、`plan`（计划模式）、`read_file/list_dir/search`（只读）、`request_user_input`。
MCP 客户端列入二期；协议上 `ToolSpec` 已兼容动态注册。
**备选**：直接 shell 自由文本写入——无法审计无法审批，**拒绝**。
**状态**：已决定。

### ADR-005：前后端通信协议

**决策**：单一事件协议 `EventMsg`（Rust enum，serde tagged），参考 codex protocol。事件类型首批：`AgentMessageDelta`、`ToolCallBegin/OutputDelta/End`、`ExecApprovalRequest/Resolved`、`PlanDelta`、`TurnStarted/Completed`、`TurnDiff`、`Error`、`TokenUsage`。
后端 → 前端：Tauri `emit` 广播（事件流）；前端 → 后端：`invoke` 命令（send_task、approve、cancel、set_config）。
**持久化**：`rollout/` 将每轮请求/响应/工具调用写 JSONL（`RolloutItem::{ResponseItem, Compacted, SessionMeta}`），支持 fork/resume。
**备选**：WebSocket 双工——Tauri 内嵌场景无必要，**拒绝**。
**状态**：已决定。

### ADR-006：前端架构（复刻 deepseek-harness）

**决策**：
- 状态：zustand vanilla + immer + subscribeWithSelector 的**快照存储**（`createSnapshotStore` 模式），React 层只订阅选择器；
- 流式 Markdown：增量解析器 + 冻结块缓存（`MarkdownText`/`StreamingRenderer` 模式）——已完成的块不再重渲染；
- 会话建模：conversation-nodes 模式——`user/message`、`tool_call`、`approval`、`diff` 统一为 node 流；
- 组件基元：`DiffBlock`（hunk 渲染）、`TerminalBlock`（限行数+状态）、`ApprovalCard`、`PlanBlock`；
- 传输层抽象：`transport` 注入（Web 开发模式用 mock，Tauri 模式用 IPC），保证前端可脱离后端用 Vite 独立开发。
**关键依赖**：`react-markdown`+`remark-gfm`（或自研增量解析）、`shiki`（代码高亮）、`xterm.js`（二期交互终端）、`zustand`、`immer`、`clsx`、Tailwind CSS。
**状态**：已决定。

## 6. 风险登记册

| 风险 | 可能性 | 影响 | 缓解 | 决策记录 | Owner |
| --- | --- | --- | --- | --- | --- |
| Windows 受限令牌绕过/实现缺陷导致沙箱失效 | 中 | 高 | deny-ACE 探针测试（FF-3/4）；M2 前以"逻辑边界+醒目提示"明示降级状态 | ADR-002 | ASSUMED: sandbox 模块 |
| API Key 泄漏（日志/提示词/rollout） | 中 | 高 | Key 仅存 Windows DPAPI 加密区；日志与 rollout 写入前脱敏过滤器；AGENTS.md 数据边界 | ADR-005 | ASSUMED: config 模块 |
| Agent 无限循环烧 token | 高 | 中 | 每任务最大轮数+token 预算硬上限；费用超阈值自动暂停并询问 | ADR-001 | ASSUMED: agent_loop |
| apply_patch 幻觉产生损坏补丁 | 中 | 中 | 补丁应用前 dry-run 校验；失败自动回滚并将错误回填给模型 | ADR-004 | ASSUMED: apply_patch |
| 审批疲劳导致用户无脑放行 | 中 | 高 | "本会话记住"仅限 execute 级；destructive 永不记忆；审批 UI 默认焦点在"拒绝" | ADR-003 | ASSUMED: permission |
| 全 AI 编程产生架构漂移 | 高 | 中 | AGENTS.md 强制小步提交+健身函数+本文档为唯一事实来源；每次会话开工必读 | 全部 | ASSUMED: 用户+AI 代理 |

## 9. 产品目录结构（安装与运行时）

产品提供两种发行形态：**安装版（MSI）**与**便携版（ZIP，免安装）**。两者共用同一套数据目录布局，仅根目录不同，由启动时的目录解析逻辑决定（见本节末尾）。

### 9.1 安装版（MSI）

安装目录与运行时数据严格分离；卸载默认保留用户数据，提供"同时删除数据"选项。

```
C:\Program Files\SHANIU\          # 安装目录（MSI，只读）
├── SHANIU.exe                    # Tauri 主程序
└── resources\                    # 前端打包产物、内置资产

%APPDATA%\SHANIU\                 # 用户配置与密钥（随用户漫游可选）
├── config.toml                   # 模型端点、沙箱策略、审批模式
├── secrets\                      # API Key（DPAPI 加密，仅当前用户可解密）
│   └── <provider>.key
└── settings-backup\              # 配置变更前自动备份（保留最近 5 份）

%LOCALAPPDATA%\SHANIU\            # 本机数据（不漫游）
├── sessions\                     # 会话索引（session meta + 摘要）
│   └── <session-id>.json
├── rollouts\                     # 会话完整轨迹（JSONL，支持 fork/resume/replay）
│   └── <session-id>.jsonl
├── logs\                         # 应用日志（写入前经脱敏过滤器，按天滚动，保留 14 天）
│   └── shaniu-YYYY-MM-DD.log
├── cache\                        # 模型响应缓存、token 计数缓存（可安全清空）
└── crash\                        # 崩溃转储（待用户确认后才可上报）

<用户工作区>\                     # Agent 操作的项目目录（用户指定）
└── .shaniu\                      # 工作区级数据（可选）
    ├── plan.md                   #   Plan Mode 已批准计划
    └── ignore                    #   Agent 不可读路径清单（追加于沙箱策略之上）
```

### 9.2 便携版（ZIP，免安装）

```
SHANIU-Portable\                  # 解压即用，可整体放在 U 盘/同步盘
├── SHANIU.exe                    # 主程序（与安装版同一构建产物）
├── resources\                    # 前端打包产物、内置资产
├── portable.marker               # 便携模式标记文件（存在即启用便携模式）
└── data\                         # 全部用户数据，等价于安装版 %APPDATA% + %LOCALAPPDATA% 之和
    ├── config.toml
    ├── secrets\                  # API Key（见边界规则第 4 条）
    ├── settings-backup\
    ├── sessions\
    ├── rollouts\
    ├── logs\
    ├── cache\
    └── crash\
```

### 9.3 数据目录解析（启动时）

按优先级解析，首个命中生效，解析结果写入日志第一行：

| 优先级 | 条件 | 数据根目录 |
| --- | --- | --- |
| 1 | 环境变量 `SHANIU_DATA_DIR` 已设置 | 该路径（用于测试/CI/多实例隔离） |
| 2 | exe 同目录存在 `portable.marker` | `<exe 目录>\data\`（便携模式） |
| 3 | 默认 | `%APPDATA%\SHANIU\` + `%LOCALAPPDATA%\SHANIU\`（安装模式） |

**边界规则**：
- 沙箱 `workspace-write` 的作用域 = `<用户工作区>`，SHANIU 自身数据目录（安装版的 `%APPDATA%`/`%LOCALAPPDATA%`，便携版的 `data\`）**默认对 Agent 拒绝读写**（防止 Agent 篡改自身配置/密钥/日志）；便携模式下 Agent 工作区若为 `SHANIU-Portable` 的父目录，必须把 `data\` 显式加入拒绝清单。
- `secrets\` 只能由 `config.rs` 读写；DPAPI 加密**绑定当前机器当前用户**——便携版整体拷贝到另一台机器后密钥不可解密，启动时检测解密失败则标记密钥失效并引导用户重新输入（fail-closed，不回退为明文存储）。
- `logs\` 与 `rollouts\` 落盘前统一过脱敏过滤器（见风险登记册 R2）。
- 便携版常位于可移动/未加密介质：首次启动便携模式时提示一次数据落盘位置与加密建议（如 BitLocker To Go），用户可关闭提示。
- 两种形态共用同一构建产物与同一套代码路径，差异仅在数据根目录解析；禁止为便携版维护独立代码分支。
