  模型收到的原始输出（call_2644075dacf245cba3ca756b）：
    拒绝说明：type=user_denied；工具=unified_exec；范围 approval=on_request sandbox=workspace_write risk=execute
    用户拒绝了这次调用，这条不会被自动放行。
    可行做法：说明这次操作要达成什么，或换一个更小的动作再问；不要原样重试，也不要换个说法绕过审批。
  界面同一张卡：
    折叠标题  「工具调用unified_exec · python -c …」，无「已拒绝」；DOM data-state="ok"
    展开正文  与上面逐字相同（含「可行做法：…」），但默认折叠（shots/F5-user-denied-card.png 为所在会话）
  模型回复（节选）："命令未执行——审批被拒绝，工具返回原文如下（未改动）：\n\n```\n拒绝说明：type=user_denied；工具=unified_exec；范围 approval=on_request sandbox=workspace_write risk=execute\n用户拒绝了这次调用，这条不会被自动放行。\n可行做法：说明这次操作要达成什么，或换一个更小的动作再问；不要原样重试，也不要换个说法绕过审批。"
    并列出 3 条更小动作让用户选（1–100 先验证 / 授权完整输出 / 落文件）。

三、结论口径
  原因文本一致（界面展开态 = 模型侧逐字），可行动替代也一致（都在同一条输出 + 模型回复里）。
  不一致的是「状态信号」：两类拒绝在 UI 上都渲染成 data-state="ok"，标题不标已拒绝/失败，
  不展开就看不出这条没有执行。
