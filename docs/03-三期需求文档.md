## 2. T1 插件 UI 沙箱

**需求**：允许第三方插件在独立 WebView 中渲染自定义 UI（如可视化面板），参考 ZCode `pluginSandbox` 设计：

- guest webPreferences 硬化：context isolation + sandbox + webSecurity 开启，node integration/plugins/dialogs 全关（对应 ZCode `guestPolicy.ts`）。
- 权限闸门（`PluginSandboxPermissionGate` 模式）：资源级权限（camera/microphone/clipboard 等）按声明 + 首次使用审批，审批弹窗由 Rust 后端发出，guest 页面不可伪造。
- 会话期同意记录，导航限制在声明 origin，拒绝 popup 与下载。
- 与 Agent 的关系：插件 UI 仅消费事件，**无权限直接调用工具**；插件产出的内容进入模型上下文前按 MCP 同级的不可信标记处理。

**风险**：插件投毒与权限蔓延 → 毕业前必须走 `llm-application-security` + `client-application-security` 双评审。

## 3. T2 MCP streamable HTTP

- 在 `mcp_client` 增加 HTTP 传输实现，stdio 与 HTTP 共用工具注册/信任模型/注入防护管线（ADR-105 不变）。
- HTTP server 默认 `review` 信任级（网络面天然不可信），不支持静默升级 `trusted`。
- 远端 server 的凭证存 DPAPI `secrets\`，禁止写入 config.toml 明文。

## 4. T3 远程子代理执行器

- 将 02 ADR-101 中的子代理执行器抽象为 trait（`AgentExecutor`）：进程内实现为默认；远程实现（SSH/容器）作为可选后端。
- 触发条件（Revisit Trigger）：用户需要在工作区以外执行（如构建集群）、或需要 OS 级强隔离子代理。
- 未触发前**不实现**，仅保证 trait 边界存在。

## 5. T4 自动更新与崩溃上报

- tauri updater：签名校验、增量更新、失败回滚；更新通道在设置中可选（stable/beta）。
- 崩溃转储（`crash\`）上报为**显式 opt-in**，上报前展示内容预览，走脱敏过滤器。
- 毕业前走 `production-readiness-review` + `release-build-reproducibility`。

## 6. T5 多代理评估基线

- 建立固定任务集（10–20 个典型编码任务）作为回归基准：成功率、完成轮数、token 成本、越权拦截率。
- 每次 M5+ 里程碑合并前运行；指标退化 >10% 阻断合并。
- 实施细节由 `llm-evaluation` specialist 输出。
